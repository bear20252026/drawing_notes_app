# Notes 页面可编辑载荷边界重构

**作者：Manus AI**  
**日期：2026-08-27**  
**目标分支：`refactor/notes-page-content-boundary`**

## 1. 改造动机

`NotebookPage` 当前同时保存页面库元数据、可编辑画布内容、版本快照、克隆引用和模板信息。虽然聚合规模尚未超过行数门禁，但**同一组可编辑字段**——画布、文字、图片、连接线、形状与图表——已在自动保存、版本恢复、内容变更判断和版本序列化中重复出现。特别是，展示层的 `_save` 和 `_showHistory` 均手写 JSON 往返深拷贝，导致页面载荷的复制、签名与恢复语义分散在不同 `part` 文件中。

> 本批次不改变页面 JSON 的字段名、版本历史的保留上限、加密存储策略、编辑器持有的对象引用或界面流程；只把“完整可编辑页面内容”的领域语义收口为稳定契约。

| 已发现问题 | 根因 | 本批次措施 |
|---|---|---|
| 自动快照与恢复各自枚举六种可编辑对象 | 页面内容缺少独立值对象 | 引入 `NotebookPageContent`，作为完整可编辑载荷的唯一表示 |
| 深拷贝散落在展示层 | 复制约定不是领域 API | 由 `deepCopy()` 和 `PageVersion.capture()` 统一生成可回溯快照 |
| 变更判断依赖展示层私有 JSON 签名 | “页面是否有内容/是否已变化”不属于 Widget | 由载荷提供 `isEmpty`、`signature` 和 `hasSameContentAs()` |
| 恢复流程逐项清空和复制 | 页面内可变集合的替换规则无契约 | 由 `NotebookPage.restoreContent()` 统一深拷贝恢复，同时保留现有 `DrawingDocument` 引用 |
| `notebook.dart` 集中所有领域类型 | 边界不清、演进成本上升 | 将模板、克隆引用、可编辑载荷、版本快照及笔记本聚合拆为职责单一的 domain 文件 |

## 2. 目标领域结构

| 类型 | 责任 | 明确不负责 |
|---|---|---|
| `PageTemplate` | 页面创建模板到纸张和无限画布策略的映射 | 创建 Widget、初始文字布局 |
| `CloneRef` | 表达跨笔记本源页面定位 | 加载、解析或写回源页面 |
| `NotebookPageContent` | 表达、序列化、比较、深拷贝和恢复完整可编辑载荷 | 页面标题、标签、模板、收藏、历史管理、I/O |
| `PageVersion` | 为指定时间点保存不可变语义的内容快照及摘要 | 直接修改活动页面 |
| `NotebookPage` | 维护库元数据与活动内容引用；协调快照、恢复和历史上限 | UI、存储、通知、加密 |
| `Notebook` | 维护笔记本元数据、页面集合与脱敏搜索摘要 | 页面编辑交互、密码或密钥操作 |

## 3. 迁移策略

`NotebookPage` 继续公开既有的 `document`、`textItems`、`imageItems`、`connectors`、`shapes` 与 `charts` 访问器，以保证编辑器会话和已有调用方保持源兼容。访问器转发到唯一的 `content` 实例，因此不会产生第二套活动内容状态。

`PageVersion` 同样保留现有的六个访问器和旧构造参数，以保证已有 JSON 与测试使用方式稳定；新增的 `content` 和 `capture()` 是更高层的完整载荷入口。新旧 JSON 都维持原字段形状，避免存储迁移和加密笔记本兼容风险。

展示层将只保留保存调度、确认对话框、状态刷新和持久化调用。快照创建、内容比较、深拷贝恢复、版本截断全部迁移到聚合或载荷对象，使 Widget 不再需要理解全量对象集合。

## 4. 必须保持的不变量

| 不变量 | 验收方式 |
|---|---|
| 历史版本必须覆盖六类可编辑对象 | 序列化、快照与恢复直接测试 |
| 版本快照与活动页面不能共享可变集合或对象 | 修改活动内容后验证快照内容不变 |
| 恢复旧版本不能替换编辑器正在持有的 `DrawingDocument` 对象 | 验证恢复后文档身份不变且内容完整更新 |
| 版本上限仍为 `NotebookPage.maxHistoryVersions` | 通过聚合 API 验证截断行为 |
| 任何可编辑对象变化都能触发新版本 | 分别覆盖笔画、文字、图片、形状、图表、连接线的签名差异 |
| JSON 字段保持兼容 | 既有 round-trip 测试与全量回归测试 |
| 克隆页仍由展示层跳过本地版本写入 | 保留 `_save` 中现有克隆判断 |

## 5. 非目标

本批次不引入持久化仓储重写、不可变 Redux 状态树、自动迁移脚本、版本差异算法升级、克隆解析服务或模板生成器。这些方向会扩大为存储或产品行为变更，应该在独立 PR 中设计和审查。

## 6. 验证计划

新增领域直接测试，覆盖完整内容的 JSON 往返、深拷贝隔离、签名变化、恢复时引用保持、自动版本截断与各类内容变更。完成后执行格式化、串行 Flutter 全量测试、静态分析、边界脚本和 diff 检查，并在 PR 中等待受保护 `master` 所需的完整远程门禁。
