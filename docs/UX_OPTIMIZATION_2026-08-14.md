# 绘图笔记 App：体验优化说明

**作者：Manus AI**  
**日期：2026-08-14**  
**范围：Flutter 桌面/Android 项目中的编辑器体验与产品能力对标**

## 结论摘要

本次审阅的核心结论是：现有应用并非“功能不足”，而是已经把绘图、笔记、图层、导出、演示、图表、计时和安全能力同时放进了编辑器主界面。编辑器 `EditorPage` 达到 4,600 余行，原有界面同时常驻左侧工具栏、横向工具栏、图层面板、属性面板、状态栏、小地图和番茄钟。这样的布局让画布被挤压，也使用户难以判断当前应先选择工具、修改属性，还是管理图层。

本次改造遵循 **“画布优先、工具分层、属性随选中对象变化、低频功能按需出现”** 的原则。该原则参考了 Excalidraw 将工具、场景状态、可选 UI 和宿主回调分离的设计方式，以及 OneNote/Goodnotes 将书写、选择和资料管理转变为明确工作流的产品体验。[1] [2] [5] [6]

> **改造目标不是复制 Excalidraw 的界面或代码，而是借鉴其真实的产品结构：把高频创作路径保持简短，把复杂功能变成有上下文、可发现、但不打扰画布的能力。**

| 改造目标 | 已完成的实现 | 用户可直接感知的变化 |
| --- | --- | --- |
| 让画布成为默认焦点 | 图层与详细属性面板改为按需展开 | 打开编辑器时获得更宽的创作区域，避免右侧双面板长期占宽 |
| 降低工具栏噪声 | 新增上下文工具条，替换堆叠的横向工具栏 | 未选中对象时只显示笔触颜色/粗细；选中文字或形状时只显示相关属性 |
| 统一主要入口 | 左侧工具栏承担画笔、橡皮、选区、文字、形状、连线和手型平移 | 工具位置稳定，减少在顶栏与侧栏之间来回寻找 |
| 降低模式误操作 | 手型、形状、框选、连线、文字、吸管等主模式改为互斥 | 切换工具后不会遗留多个竞争状态，减少“拖动画错、点击无反应”等困惑 |
| 整理低频行为 | 顶栏移除重复的导出与清空按钮，统一收纳至主菜单 | 顶栏更简洁；导出 PNG/SVG/PDF/JSON/PPTX/文本仍完整保留 |

## 对 Excalidraw 的研读与可借鉴边界

Excalidraw 的编辑器本体是可嵌入的组件，公开 API 将初始场景、变更回调、主题、网格、禅模式、UI 定制、事件处理与导出工具分开提供。[2] 其源码还使用统一的动作管理器，将快捷键、菜单与面板动作连接至同一 `perform` 逻辑，从而避免同一行为在多个入口中实现多次。[1] 这些设计与本项目已有的 `CommandRegistry` 方向一致，因此适合继续深化，而不需要迁移技术栈或嵌入 Web 编辑器。

| Excalidraw 的真实能力 | 对本项目的正确借鉴方式 | 当前建议 |
| --- | --- | --- |
| 工具、场景状态和 UI 可配置 | 以“左侧选工具、中央显示上下文参数、右侧按需管理”为信息架构 | **已实施第一版** |
| `onChange` 驱动宿主保存 | 保持现有本地优先、800ms 防抖保存；后续以变更版本和冲突策略增强 | 保留现有设计 |
| PNG、SVG、剪贴板与开放场景数据导出 | 继续维护 PNG/SVG/JSON；导出应有背景、尺寸、文件名等明确选项 | 已有能力，后续完善导出对话框 [3] |
| 图形库、元素链接与选择变换 | 先做可持久化模板库、对象语义链接、可靠的框选/对齐/分组 | 中期优先 |
| 实时协作入口 | 只有接入同步服务、身份、权限、冲突处理和协作协议后才可提供 | **不应直接复制**；官方文档也明确协作需要额外服务端支持 [4] |
| 无限画布 | 保持为白板工作区，不与“纸张笔记页”混为一个默认模式 | 建议作为单独创建类型或模板 |

本项目不能直接嵌入 Excalidraw：其编辑器建立在 React/Web Canvas 生态上，而当前应用是原生 Flutter CustomPainter 架构。更合适的路径是继续用 Flutter 引擎保存本地离线与跨平台优势，同时借鉴其产品抽象、元素模型、统一命令与工具布局；不复制其源码和视觉资产。

## 商用笔记与画图产品的体验基线

OneNote 将“绘制”作为与输入明确切换的工作方式，并把套索选择与墨迹转文本设置为连续的任务流程。[5] Goodnotes 则强调书写、键入、草图、导入资料和模板的统一工作区，并把手写检索、批注、文档导入和协作视为笔记系统的一部分。[6] 因此，用户愿意长期使用的不是工具数量最多的应用，而是能够让其迅速完成“记录—整理—再次找到”的应用。

| 能力方向 | 现有基础 | 推荐产品化方式 | 优先级 |
| --- | --- | --- | --- |
| 快速记录 | 已有“快速记录”入口、本地自动保存 | 打开即进入空白模板或最近页面，名称延后处理 | P0 |
| 手写与对象选择 | 已有笔画、套索、框选、移动/缩放/旋转 | 补充更清晰的选择框、对象边界、Esc 退出和 Delete 提示 | P0 |
| 模板与纸张 | 已有空白、网格、横线、点阵 | 新建时选择“会议记录、方格、康奈尔、项目看板、无限白板” | P1 |
| 搜索与归档 | 已有标题/文本搜索 | 建立标签、收藏、最近使用、笔记本筛选；手写 OCR 应在数据与隐私方案成熟后再做 | P1 |
| 文档批注 | 已有图片插入 | 先支持 PDF 页面导入与墨迹标注，再考虑多格式文档 | P1 |
| 可复用模板/形状库 | 已有会话内形状库 | 持久化个人模板，提供分组、搜索、拖入画布和导入/导出 | P1 |
| 同步与协作 | 当前明确离线本地优先 | 先做可靠备份/恢复，再做端到端加密同步；实时协作最后实施 | P2 |
| 手写识别与智能整理 | 当前无 OCR/AI | 仅在用户明确要求且给出离线或隐私边界后设计 | P2 |

## 已完成的代码改造

### 1. 新建上下文工具条

新增 `lib/ui/widgets/editor_context_bar.dart`。该组件仅在当前对象需要时展示相应控制项：普通绘制状态显示颜色与笔触宽度；选中文字时显示字号、颜色、加粗、斜体、下划线与对齐；选中形状时显示线宽、填充、虚线与删除。它复用既有的 `EditorToolbarState` 和 `EditorToolbarActions`，因此没有复制业务逻辑。

### 2. 改造编辑器主界面

`EditorPage` 默认不再常驻图层面板和属性面板。用户可从应用栏中的两个明确入口展开“图层”或“属性”，需要管理时仍可使用原有能力。左侧保留为主要工具带，中央为上下文属性，右侧为按需管理。该结构更接近画图软件中“工具—画布—检查器”的稳定心智模型。

### 3. 增加手型平移并修复模式互斥

左侧工具栏补上了此前已声明但未显示的手型平移入口。手型、框选、形状和连线模式会主动关闭其他竞争状态；画笔、橡皮、文字和吸管切换也会退出手型/框选/形状状态。这样可以避免相同一次拖动被多种模式解释。

### 4. 收纳低频操作

顶栏保留撤销、重做、图层、属性、全屏、帮助和主菜单。导出与清空画布改为主菜单项，减少重复入口和视觉竞争，同时保持所有原有导出格式可访问。Excalidraw 的导出 API 同样把导出作为一个独立能力，而非绘制工具的一部分。[3]

## 后续实施路线图

下一轮不建议继续向主界面堆叠功能，而应围绕真实使用任务完成闭环。第一阶段应完善 P0：将 Ctrl+K 命令面板扩展为所有编辑动作的唯一注册来源，补齐 Esc/Del/方向键微调等可见快捷键，并让选择状态、属性栏、图层面板和状态栏使用同一选中对象模型。第二阶段应做 P1：模板选择、个人形状库持久化、标签/收藏/最近使用，以及 PDF 注释工作流。第三阶段才考虑 P2 的备份、同步、协作与 OCR；协作尤其不能只新增“邀请”按钮，必须连同传输、身份、权限、离线合并和端到端加密策略一并设计。[4]
