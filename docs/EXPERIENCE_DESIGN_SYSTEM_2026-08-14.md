# 绘图笔记 App：高品质体验设计规范

**目标：让应用呈现出克制、清晰、可靠且以内容为中心的高级创作体验。**

本规范不复制 Apple 的专有视觉资产或将 Material 控件伪装成苹果系统控件。它借鉴的是可迁移的设计原则：内容优先、工具与内容分层、渐进呈现、稳定的位置记忆、目的明确的反馈和可访问的输入替代。[1] [2] [3]

## 设计原则

| 原则 | 设计决策 | 代码验收标准 |
| --- | --- | --- |
| 画布与内容优先 | 首页以最近内容为主，编辑器以画布为主；设置、导出、诊断进入次级入口 | 首屏不出现超过一个主操作；编辑器不常驻低频面板 |
| 功能分层 | 左侧是导航，顶部是当前内容与高频动作，右侧是按需检查器 | 单一工具栏最多三个逻辑分组；低频动作进入菜单 |
| 视觉静谧 | 使用暖中性色背景、单一靛蓝强调色、柔和边界和一致圆角；避免将每张卡片都高对比上色 | 深浅主题均有明确表面层级，正文/次要文本使用主题语义色 |
| 反馈真实 | 保存、压感、搜索、删除、加载都提供短暂且可理解的状态；不以无意义动效掩盖耗时 | 所有异步高频入口具备加载/错误/完成状态 |
| 动效克制 | 只对布局出现、选择状态和面板展开使用短动画；直接跟随拖动，不让用户等待动画 | 页面结构动画不超过 220ms；启用“减少动效”时改为淡入或关闭 |
| 无障碍可达 | 重要动作有文本/工具提示、键盘路径和足够命中区；颜色不单独传达状态 | 删除、收藏、压感、加载均有图标之外的语义；可用键盘/触控完成主路径 |

Apple 的布局规范强调为主要内容预留足够空间，并把次要信息放到附加视图；其工具栏规范要求限制项目数量，按频率与功能分组，并把次要操作放入更多菜单。[1] [2] 因此本应用不追求“所有功能同时可见”，而追求用户在正确时机准确找到所需功能。

## 信息架构

| 页面 | 主要任务 | 首屏结构 | 次级能力 |
| --- | --- | --- | --- |
| 首页 | 继续最近工作、创建内容、进入资料库 | 欢迎标题、全局搜索、最近更新、主创建按钮 | 画作/笔记本/时间线切换、主题、密码盘 |
| 笔记本库 | 浏览、筛选、整理、进入页面 | 笔记本标题、搜索/标签筛选、新建页面、排序后的页面网格 | 加密、文本导入、跨本引入、批量整理 |
| 编辑器 | 书写、绘图、选择、变换、保存 | 文档标题、撤销/重做、侧栏切换、主工具条、画布 | 图层、属性、导出、演示、形状库、统计、快捷键 |

## 布局令牌

| 令牌 | 数值与规则 | 用途 |
| --- | --- | --- |
| 页面外边距 | 20（紧凑时 12） | 首页、笔记库和空状态的稳定留白 |
| 组件间距 | 4 / 8 / 12 / 16 / 24 / 32 | 避免随意的边距值造成节奏混乱 |
| 交互高度 | 常规 44，紧凑 36 | 触控可达与桌面密度之间的平衡 |
| 圆角 | 容器 18，输入与按钮 12，小型标记 8 | 形成统一、温和但不过度拟物的轮廓 |
| 内容背景 | 浅色为暖灰白；深色为蓝黑灰 | 让纸面、缩略图和画布保持视觉中心 |
| 强调色 | 单一靛蓝，不以多色装饰工具栏 | 用于选择、主操作、焦点与关键状态 |

## 动效与可访问性策略

动效必须解释状态、反馈操作或保持空间连续性；频繁工具切换不应加入延时动画。[3] 系统的无障碍规范还要求保持足够的文字对比、提供足够大的控制区、支持键盘和不依赖颜色传达状态。[4]

| 场景 | 默认反馈 | 减少动效时 |
| --- | --- | --- |
| 首页/库卡片加载 | 180ms 淡入 | 立即出现 |
| 面板展开/收起 | 180–220ms 尺寸与淡入 | 短淡入或立即切换 |
| 收藏/选中 | 120ms 颜色与轻量缩放 | 仅颜色/图标变化 |
| 保存状态 | 不阻塞的文本状态变化 | 相同 |
| 拖动/书写 | 直接跟随输入，无延迟缓动 | 相同 |

## 功能闭环验收

所有新功能都必须通过以下问题：用户能否在 3 秒内理解它？能否在一次会话中完成它？结果是否保存并在重开后保留？失败时是否给出可行动的说明？如果任一项为否，功能应进入后续迭代而不是增加图标。
