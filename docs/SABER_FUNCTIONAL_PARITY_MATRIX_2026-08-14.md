# Saber 功能等效验收矩阵

**目标：** 在不复制 Saber GPLv3 源码的前提下，以独立实现方式让当前绘图笔记应用达到 Saber 当前用户可感知功能的等效水平，并在每项交付前完成端到端验证。  
**参考基线：** Saber 源码提交 `f534abb3a29ad9fa15d7bb83a5b69593477cda6c`、README、官方路线图和源码模块。  
**状态定义：** `已具备` 表示已有真实代码与回归测试；`部分具备` 表示有数据/入口但任务闭环或平台验收不足；`未具备` 表示需要新建能力。  

> **合规约束：** Saber 及其 SBN 包为 GPLv3。下表中的“学习来源”仅代表可独立重写的功能与工程思路，**不授权复制其 Dart、Flutter Widget、数据格式、内部模块或注释**。若将来把本项目整体改为 GPLv3 并公开相应源代码，才可另行评估直接复用。[1]

## 范围说明与阶段门禁

**阶段 1（编辑基础）** 必须先完成 A01–A14、B01–B09、B13、C01、D02/D05、E01、F04/F07/F08，才能宣称“与 Saber 相当的核心书写体验”。其重点是把已有绘图与命令基础收口为稳定的手写工具，而不是新增更多入口。

**阶段 2（资料型笔记）** 完成 PDF 批注、资料库和图片/文本/页面工作流。只有 D01 与 D03 满足导入—编辑—保存—重开—导出闭环，才开放 PDF 功能；只有 C02–C09 完成，才将首页宣传为“资料库”。

**阶段 3（长期文档与交付）** 完成格式演进、大文件后台加载、导出混合渲染、备份恢复和多语言。它是稳定商业发行的可靠性门槛。

**阶段 4（同步与隐私）** 是完整 Saber 同步能力最复杂的部分。必须先完成本地备份、冲突模型、密钥管理、网络失败测试和隐私说明；任何一个前置条件缺失，都不得在正式版本显示“已同步”。

**阶段 5（平台与发布）** 才扩大到 iOS/macOS/Linux、自动更新和完整发布矩阵。Windows/Android 是当前优先真实验收平台。
