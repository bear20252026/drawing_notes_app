# 多项目数据完整性修复验收记录

**日期：** 2026-08-14  
**问题等级：** 阻断性数据完整性故障。  
**覆盖范围：** 独立无限画布、分页笔记本、自动保存、退出重开、缩略图与内存渲染隔离。

## 一、已确认的根因

用户报告的“画布 A 与画布 B 退出重开后消失、内容交叉或重叠”不是单一界面问题，而是以下三类风险叠加造成的。

| 风险 | 旧行为 | 后果 |
|---|---|---|
| ID 生成 | 仅使用微秒时间戳 | 高频创建可能形成同 ID，导致工程文件和缩略图路径相同 |
| 自动保存 | 保存中直接跳过后续请求；退出时取消防抖、异步保存未等待且控制器立即释放 | 最后一次修改可能没有落盘；缩略图渲染可能在控制器释放后失败 |
| 文件替换 | 所有写入复用固定 `.tmp`；依赖直接重命名覆盖旧文件 | 同文档快速写入可抢占临时文件；部分 Windows 文件系统上已有目标的替换可能失败 |
| 笔记本保存 | `_saving` 为真时直接返回 | 保存期间发生的后续页面修改可能不会保存 |

> **结论：** 先前“内容没有了”与“内容串到另一项目”都有可解释的持久化边界缺陷，已按文档 ID 隔离、保存快照与关闭前落盘三个层级完成修复。

## 二、实施的防线

### 2.1 ID 与文件路径隔离

新增 `LocalIdGenerator`，由**时间、进程序号和安全随机熵**生成只含安全文件名字符的 ID。独立画布、笔记本、页面和形状等本地对象均经原有 `StorageService.newId` 或 `NotebookStorage.newId` 使用该策略，避免高频创建产生相同工程文件名或缩略图名。

### 2.2 独立画布落盘队列

`StorageService` 现在以文档 ID 为键维护写入尾队列。相同文档的多个保存请求按发起顺序串行，不同文档可并行而不会共用临时文件。每次请求在进入队列前立即编码 JSON 快照，因此 A/B 文档继续被编辑时不会把可变内存对象混写到旧请求中。

临时文件名已加入唯一随机 ID；正式文件替换前先保留 `.bak`。若 Windows 拒绝覆盖已有目标，存储层会在备份存在的条件下执行安全回退替换。读取时正式文件不存在或格式损坏会自动尝试 `.bak`。

### 2.3 关闭前与保存中变更处理

独立编辑器的防抖保存回调现为可等待异步任务。用户通过正常返回离开编辑器时，页面会先取消未触发的防抖并等待当前及后续补写保存完成，再执行返回。保存进行中出现的新更改会设置补写标记，当前保存结束后立即保存最新版本，不再被“正在保存”条件丢弃。

极端情况下系统直接销毁页面无法等待 Future，编辑器仍优先启动文档 JSON 保存，并跳过可再生的缩略图生成，避免释放控制器后导致正文保存路径受影响。

### 2.4 笔记本与显示状态

笔记本存储采用同样的按 ID 队列、唯一临时文件、备份恢复策略；笔记本页面的 `_save` 在保存中收到新的变更时也会补写。绘图控制器的图层缓存保持实例私有，新增并行 A/B 控制器测试确认活动笔画、图层数据和控制器对象无共享引用。

## 四、用户复验步骤

1. 新建两个无限画布，命名为 **A** 和 **B**。在 A 左上写 `AAA`，在 B 右下写 `BBB`，并各自放一个形状。
2. 分别返回首页，等待 1 秒让缩略图刷新；完全关闭应用后再打开。
3. 从首页分别打开 A、B。预期 A 只含 `AAA` 和 A 的形状，B 只含 `BBB` 和 B 的形状；两者标题、缩略图和内容不得交叉。
4. 对其中一个画布连续快速书写后立即按返回。再次打开时，最后一笔也应存在。
5. 对两个不同笔记本分别新建页面、输入不同文字后退出重开，确认页面和文字只属于各自笔记本。

如果实体设备上仍复现某一项目错乱，请保留该项目名称、创建顺序、操作时间和复现步骤；当前存储修复已将正式文件与 `.bak` 分开保存，可据此进一步定位异常设备上的遗留文件。
