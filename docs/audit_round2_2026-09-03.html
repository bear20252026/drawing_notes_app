一、本轮新发现6 项 · 全部有代码证据

中 R1. WebDAV 同步错误提示仍拼裸异常 —— 首轮 P2-21 的扫尾遗漏

webdav_sync_settings_page.dart:153「同步失败：${outcome.error}」· :166/:167/:169「同步初始化失败：$e」

首轮审计只清了 runtimeType / snapshot.error 两类模式，WebDAV 页把异常对象 $e 直接拼进用户可见的 toast 与摘要里，仍会出现「同步初始化失败：SocketException: …」级别的开发者腔。

修法：错误文案映射为人话（网络/认证/服务器三类），原文进调试日志；纯文案层，零行为变化。

中 R2. 390dp 溢出门禁只覆盖 2 处页面 —— U6 已证明此类盲区真实咬人

test/app_shell_smoke_test.dart:71 · test/features/drawing/presentation/editor_page_390dp_overflow_test.dart:16（仅此两处）

回收站 / 搜索 / 标签 / 日程 / 设置 / 笔记编辑页（DocPage）/ 分页画布页（NotebookViewPage）共 7 个有移动布局的页面没有任何 390dp 溢出探针。U6 刚刚实测证明：0 宽容器不报溢出、既有缺陷门禁测不出来。窄屏回归防线目前是「半个筛子」。

修法：为 7 个页面补 390dp 探针测试（takeException isNull 模式照抄既有门禁）——纯新增测试，零产品代码改动，预计一次性找出若干隐藏溢出（找出的再逐个修）。

中 R3. Windows 桌面窗口无最小尺寸约束

pubspec.yaml 无 window_manager 系依赖 · main.dart 仅 WidgetsFlutterBinding.ensureInitialized()（:96）

桌面窗口可被随意拖到极窄，触发与 390dp 同类的布局溢出且无任何防线；也没有最小可用尺寸保证（工具栏/侧栏挤成一团）。

修法：引入 window_manager（Windows/Android 双端兼容的成熟方案），设 setMinimumSize(360×560) + 窗口标题/居中初始化。需新增一个依赖包，先经你同意。

中 R4. 390dp 下画板顶栏 title 区仅 ~22px，长标题基本不可见（U6 遗留）

editor_page_appbar.dart（U6 修后：7 action 占满 390dp，title 区 22px；分级隐藏已消除溢出，但标题显示空间极小）

U6 修复保住了「不溢出 + 标题优先」，但根因是 7 个 action 挤满宽度。要让 390dp 下标题真正可读，需把低频 action（全屏/深色阅读/图层/属性）在窄屏收进主菜单——即首轮审计的方案 C（当时未选），现在有了实测数据支撑。

修法（需拍板）：窄屏（<600dp）时 4 个低频 action 移入主菜单分组「视图/面板」，只留撤销/重做/主菜单 3 个——标题区可从 22px 恢复到 ~200px。桌面宽屏零变化。
