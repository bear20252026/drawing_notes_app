## 当前已核验的事实

Excalidraw 官方仓库将编辑器描述为可嵌入的 MIT 开源虚拟白板，并明确列出无限画布、手绘风格、形状库、图像、开放 JSON、PNG/SVG/剪贴板导出、箭头绑定、撤销重做、缩放/平移，以及应用层的 PWA、本地优先、实时协作和端到端加密。[1]

Saber 官方仓库将产品定位为跨平台手写笔记应用，说明其可在深色模式反相笔记、图片与 PDF；高亮笔通过画布合成防止同色重叠加深且保持文字可读；并以嵌套目录、最近笔记与双密码加密同步形成笔记工作流。[2] [3]

## 研究与实现纪律

所有拟实现能力必须经过以下门槛：用户可发现的入口；真实手势/键盘输入；即时视觉反馈；撤销或明确的不可撤销语义；保存、关闭重开与导出验证；自动化测试；触控笔、PDF 或性能相关项附带 Windows/Android 真机验收。任何没有完成这一链路的功能不得以“已实现”宣称。

## 手写、对象与渲染性能深读结论

### 1. 统一对象模型不是“一个大类”，而是一组不变量

Excalidraw 的每个可协作场景元素都有统一的身份、几何、样式、角度、随机种子、版本、版本随机数、稳定层级索引、删除墓碑、群组路径、框架关系、双向绑定、更新时间、链接、锁定状态及扩展数据。其自由绘制、图片、文本、形状和连线只是带各自负载的对象变体。[5]

这说明当前工程需要从“笔画在 Layer、形状在 Document、文字/图片在 NotebookPage”的多套选择路径，逐步收敛为**可选中对象协议**。协议不要求立刻迁移所有数据，但应先统一：ID、bounds、z-order、transform、lock、group、link、serialize、hit-test、clone、delete 和 version。这是后续多选、层级、连接线、剪贴板、同步的基础。

### 2. 手写的视觉质量与几何真相必须分开

Excalidraw 对可变宽自由笔迹保存局部原始点、压力、模拟压力标记和笔触选项；恒宽笔迹走独立激光几何。其视觉常量明确属于“基于目视对比调校的经验参数”，并专门计算与画面一致的平滑中心线，以避免命中、填充等边界行为误用稀疏原始点。[6]

Saber 同样分离低/高质量轮廓，活动书写用低成本几何，完成后生成高质量路径、压缩重复点。两者共同支持以下独立原则：原始输入用于持久化；预览几何用于低延迟；完成几何用于保真；命中检测应基于呈现中心线/轮廓；参数调整必须有固定视觉样本与真机压感对照。

### 3. 渲染缓存要有失效原因和资源上限

Excalidraw 将矢量元素作为真相，但在交互中为单元素生成离屏缓存，缓存键包括主题、缩放、图像裁剪和框架透明度；当尺寸、点列或资源变化时显式失效。离屏位图有宽高及面积上限，避免移动端大对象消耗不可控内存；导出时绕过交互缓存重新生成矢量图形，保障保真。[7]

当前工程已有分页图层缓存和无限画布矢量路径，下一步不应简单“全场景位图化”，而应实施：对象级缓存仅用于复杂/静态对象；持续书写维持矢量预览；缓存带缩放与主题版本；图片/PDF 建立可见性加载与内存预算；导出绕过显示缓存。

### 4. 绑定是受维护的图关系

Excalidraw 的箭头端点不只是存两个坐标，而是可以存对象 ID、旋转相关固定点比例和 inside/orbit/skip 模式。关系图在对象移动、缩放、旋转、复制、删除时都要修复双向绑定和端点几何。[5]

当前笔记页已有连接线字段、独立画布仍无正式绑定。后续连接线应先建立小而完整的图关系内核：端点对象 ID + 归一化锚点 + 箭头样式 + 断开策略；再增加吸附、肘形路线、标签与流程图自动布局，不能先画“看起来像线”的静态装饰。

## 笔记、开放格式、协作与安全深读结论

### Excalidraw：开放场景与协作分层

Excalidraw 的公开场景格式将场景级元信息与元素数组分开。每个元素共享身份、几何、样式、版本、稳定顺序、删除墓碑、分组、框架、绑定、链接和锁定字段；图片文件独立保存在以 `fileId` 为键的资源对象中。形状标签不是嵌入形状字段，而是独立文本元素加双向绑定；箭头端点使用对象 ID 和归一化锚点，而不是只保存绝对坐标。[9]

官方端到端加密文章说明免费版默认不将绘图发送到服务器；共享场景时，客户端用随机对称密钥在上传前加密内容，并将解密材料放在 URL fragment（fragment 不发送给服务器）。这提供“服务器只保存密文”的共享模型，但也意味着持有链接与密钥的一方拥有访问能力。[10] 这种短期共享密钥模型适用于即时协作链接，不可直接替代账户级长期加密与密钥恢复。

### Saber：资料优先与零信任云端

Saber 的隐私策略说明：本地使用不依赖云端；如果启用云同步，笔记在发送前由随机生成的数据密钥加密，数据密钥和用户密码保存在设备安全存储，数据密钥的加密形式上传到云端。服务器仍可能看到密文文件大小、文件数、加密名称及编辑/同步时间等元数据。[11]

> 深度设计结论：当前工程应把“本地文档格式、二进制资源库、场景对象关系、渲染缓存、历史命令”视为第一阶段；云同步应作为独立的第二阶段协议，而不是直接把本地 JSON 文件上传。同步上线前必须明确：元数据泄漏范围、密钥丢失后果、共享模型、冲突策略、删除墓碑、离线队列、完整性校验与恢复流程。

| 主题 | Excalidraw 的可借鉴原则 | Saber 的可借鉴原则 | 当前工程的独立路线 |
|---|---|---|---|
| 开放格式 | 场景与资源分离；元素关系可验证 | 页面与资料资源独立保存 | 创建版本化 `scene/document + assets` 容器，保持本地 JSON 兼容迁移 |
| 文本标签 | 文本是独立对象，通过绑定成为形状标签 | 富文本与手写/图片同页 | 将当前 PageTextItem 逐步加入对象协议与容器绑定，不在 ShapeItem 重复存文字 |
| 连接线 | 端点绑定用归一化锚点，关系可修复 | 手写页聚焦更轻量资料批注 | 先完成两端绑定、移动缩放维护与删除断开，再追加路由/标签 |

| 长期同步 | 本地优先共享场景 | 独立数据密码、零信任云 | 以随机文档密钥与恢复密钥封装，设计可审计同步协议 |

## 专家级补充：关系图、层级顺序与并发一致性

### 分数层级是持久顺序，不是 UI 数字

Excalidraw 同时维护数组顺序和元素内嵌的分数层级键：数组是快速渲染缓存，分数键是可在重排、撤销和多端协调中重建确定顺序的持久事实。插入一组元素时，只为移动对象生成位于相邻上下界之间的键；发现键缺失、无效或重复时会修复连续无效组；同键冲突使用稳定对象 ID 作为确定性次序。[12]

因此当前工程的 `zOrder: int` 足以支撑单机图片与形状排序，但不应被错误延伸为未来协作排序方案。对象协议的下一版本应预留 `orderKey: String`，并在迁移阶段将旧整数映射为稀疏初始键。用户层的“置顶/置底/前移/后移”仍保持简单操作，复杂的分数键生成只存在于场景内核。

### 绑定关系必须由一个事务维护

Excalidraw 的端点绑定策略把“保留、断开、新建”视为显式状态。绑定成立后，端点的位置按目标对象的边界和归一化固定点重新投影；移动点、缩放、吸附与箭头重路由在同一关系维护流程中更新，而不是让各 UI 分支直接改坐标。[13]

本工程的独立实现不应先做可见箭头样式。最低正确单元是一个命令事务：`对象变换 -> 读取绑定端点 -> 投影到新几何 -> 更新连接线 -> 记录同一历史项`。删除时应明确断开或删除关系，而不是留下悬空 ID；复制时需生成新 ID 并只重建内部关系。

### 协作协调必须能确定性地拒绝更新

Excalidraw 在合并本地与远端场景时会保留正在本地编辑/缩放/新建的元素，版本较新的元素优先，版本相同则使用 nonce 做确定性决胜；随后按分数键排序、验证及修复排序不变量。[14] 其历史恢复刻意不复用旧版本字段，使撤销/重做作为新的用户动作参与后续协调。

> 对当前离线应用而言，此机制不是立即要复制的同步功能，而是未来模型必须预先遵守的约束：ID 稳定；对象更新有版本；删除具备墓碑语义；关系引用可验证；重放命令不覆盖其他对象的修改。

## 专家级补充：Saber 的手写性能与资料资源生命周期

### 笔画在书写中和完成后使用不同计算预算

Saber 为同一笔迹延迟缓存低质量与高质量轮廓/路径。低质量路径会跳采样、关闭平滑与压力模拟，用于持续书写的低延迟反馈；高质量路径在笔势完成后使用完整选项、可平滑曲线，并在模拟压力最终确定时去掉近距离重复点。几何或平移变化会同时失效两套轮廓和路径缓存。[15]

这验证了当前工程已有的双质量 `StrokeGeometryCache` 方向正确，但需要以**可衡量的帧预算**继续完善：活动笔画只计算受限预览轮廓；收笔在短任务中生成高质量几何；缩放、工具样式或点列变化有明确失效标识；对无限画布仅重建被修改笔画所在的最小区域。

### 资产缓存的生命周期取决于可见消费者，而不是文件是否存在

Saber 的编辑器资产缓存按本地文件路径共享 PDF/图片等解码资源，并追踪当前可见的图像消费者；最后一个可见消费者退出后可移除资源，而保存过程中会暂时禁止移除，避免写入时资源失效；编辑器销毁时统一清理 PDF 文档缓存。[16]

当前工程已经有按图片 ID 的解码缓存，但尚未有“资源被哪些可见页面/对象使用”的引用层。短期应增加：文档关闭释放所有 `ui.Image`；图片删除时保留资源文件以便撤销但解除运行时解码；PDF 页面缩略图与当前页面优先；切换页面释放非邻近页位图。中期可将 `assetId -> reference count -> decoded resource` 抽成单独 `DocumentAssetCache`，避免直接在控制器分散管理。

## 专家级补充：箭头、路由与线性元素编辑

Excalidraw 将线性元素的点列保持为局部坐标，起点归一化到 `(0,0)`；编辑时由统一线性元素编辑器维护点手柄、端点绑定、局部/全局坐标转换和线段更新。[17] 其更复杂的肘形箭头会在路由后合并共线段、删除过短段并重新编号固定段，说明“路径点”也必须满足可验证不变量，不能任由交互分支累积重复与零长度数据。[18]

当前工程第一版绑定箭头不需要复制网格寻路或肘形路线。正确的最小设计是：连接线保存 `startBinding` 与 `endBinding`（对象 ID + 归一化锚点）；渲染前/对象变换后从目标 bounds 投影端点；未绑定端点继续保存绝对点；连接线直线几何始终规范化为正宽高和 `flipX/flipY`。移动/缩放源对象、更新绑定箭头和记录历史必须作为同一命令事务。

## 专家级补充：Saber 输入调度、视口虚拟化与视图状态

Saber 的画布手势层在指针事件进入时识别触控笔、将压力从设备范围归一化到 `0..1`，并在检测到触控笔后按用户偏好自动禁用手指绘制；悬停和侧键状态也作为独立信号处理，而非混入笔画点列。[19] 其分页构建器根据当前变换后的视口 bounds，只完整构建焦点页或可见页，其他页面使用占位组件维持布局；关闭编辑器时缓存最近少量文档的视图变换，而不是长期持有完整页面树。[20]

这与本项目已经实现的输入仲裁、压力处理、分页缩略图相一致。下一步性能增强应是：在笔记本连续滚动预览中依据可见性惰性加载页面级图片/PDF 位图；保留几何占位以避免滚动跳动；将视图变换缓存限制为少量最近文档；所有对象解码缓存都在控制器 `dispose` 时释放。不可为了“性能”在书写期间触发页面树重建或同步写盘。

## 专家级补充：对象选择与变换事务

Excalidraw 的对象变换以“手势开始时原始元素快照 + 每帧从原始快照计算新几何 + 结束时提交”的事务形式组织。单对象和多对象分别处理旋转、缩放、纵横比、从中心缩放、翻转、线性点列重标定和绑定元素更新；旋转某些绑定线性对象时会显式解除不再语义正确的绑定。[21]

其选择模块把锁定对象、容器绑定文本、frame 内元素、线性元素编辑状态和组选择作为一套规则处理，而不是让不同 UI 组件各自判断。框选命中支持 contain/overlap，选择缓存仅在元素数组和 ID 集合都未变化时复用。[22]

当前工程的下一项高价值工作由此明确：独立绘图的形状需要取得和图片相同的对象编辑闭环（选择、锁定、拖动、缩放、删除、取消、撤销重做），且目标变换必须在同一事务重新投影绑定箭头。第一版不应支持旋转绑定箭头；若未来引入形状旋转，需要明确绑定端点是跟随局部几何、解除绑定还是重路由，不能静默给出错误连接。

## 专家级补充：Saber 文件导出与资源释放

Saber 的 PDF 导出按页工作：能以矢量表示的笔画直接写入 PDF 图形指令，而高亮笔和铅笔因透明度/纹理限制通过页面截图栅格化；截图工作并发数限制在 CPU 核数的一半且最多四个，避免大型文档一次性占满资源。[23] 导出前按页惰性加载背景和图片，设置超时保护，最终在 `finally` 中卸载临时加载资源并释放克隆页面数据。导出主题固定为浅色，避免用户当前深色主题污染文档产物。[23]

当前工程已经在分页笔记提供 PDF/RTF 导出，并在独立画布提供 PNG 导出。后续应采用三条约束：导出始终依赖持久对象真相而非阅读反相或低清缩略图；需要栅格化的内容限制并发并显式释放 `ui.Image`；资源加载失败/超时应输出可诊断错误而不是阻塞整个导出队列。
