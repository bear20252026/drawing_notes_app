# Excalidraw / Saber 对标差距矩阵与实施路线

**审计日期：** 2026-08-14  
**审计对象：** `drawing_notes_app`、Excalidraw `abeeaeb`、Saber `f534abb`

## 审计原则

本矩阵只将“用户能完成操作、内容可保存重开、可撤销或有明确例外、并且已有自动化或真机证据”的能力判定为**已闭环**。工具栏中存在图标、模型里预留字段或仅能演示一次的能力均不计为完成。

> Excalidraw 以无限白板、手绘图形与对象编辑器为重点；Saber 以低延迟手写、分页笔记、高亮笔、PDF 与本地优先笔记工作流为重点。[1] [2]

## 当前能力矩阵

| 能力域 | Excalidraw / Saber 参考行为 | 当前应用状态 | 差距与下一步 |
|---|---|---|---|
| 无限画布与视口 | 无限白板、平移、缩放、旋转、缩略导航 | **已闭环**：独立绘图支持无限画布、双指缩放旋转、缩略图与手型平移 | 继续加入视口性能基准与对象对齐吸附的真机验证 |
| 钢笔、铅笔、高亮笔 | 压感、平滑、粗细、颜色、工具独立预设 | **部分具备**：`perfect_freehand` 连续轮廓、真实压感优先、模拟压力回退、预设持久化；高亮笔使用不叠色合成 | 需要“实时低质量 / 完成态高质量”双质量路径、笔刷参数面板和可测视觉样本 |
| 手写视觉语言 | Excalidraw 的 variable / constant freedraw，Saber 的路径缓存与完成态平滑 | **部分具备**：连续轮廓和几何缓存已经消除粗笔大圆点问题 | 需要精细调校轮廓参数、输入去重阈值、停笔后重建、端点/纹理差异化 |
| 激光 / 临时墨迹 | Saber 的逐点尾迹消退与双层发光；Excalidraw 的恒宽自由绘制几何 | **部分具备**：高亮笔可“自动消失”，整笔约 4 秒 ease-out 淡出且不持久化 | 升级为独立激光工具：前端逐段消退、时间序列尾迹、内白外彩发光、无持久化与无历史污染 |
| 橡皮擦 | 整对象删除与局部像素擦除 | **已闭环**：整笔删除 / 透明像素擦除可切换、持久化、撤销、取消恢复 | 真机验证不同压感笔与高亮笔叠加场景 |
| 形状与识别 | 矩形、圆、菱形、箭头、线、流线图和图形库 | **部分具备**：拖拽创建 5 类基础形状，形状库；手绘矩形/椭圆保守识别、可撤销重做 | 增加直线、菱形、箭头候选识别；加入形状预览与用户确认；补齐可编辑连接点 |
| 选区与对象变换 | 框选/套索、多选、移动、缩放、旋转、复制、分组、锁定 | **部分具备**：笔画套索命中、实际墨迹中心变换、复制粘贴；混排对象具有限制性框选 | 统一笔画、文字、图片、形状为通用对象选择协议；实现多对象缩放旋转、组合/取消组合、锁定 |
| 连接线与绑定 | 可绑定箭头、标签化箭头、端点随对象移动 | **部分具备**：笔记页有连接线数据模型和基本连线模式 | 独立画布缺少连接线；需要端点绑定、布局更新、箭头样式和撤销闭环 |
| 图片 | 导入、缩放、裁剪、层级、持久化、导出 | **已闭环（导入）**：笔记页与独立画布均导入离线副本；独立画布保存重开、渲染、无限边界、PNG 导出均覆盖 | 独立画布补齐对象选择、移动/缩放/裁剪、层级、删除交互 |
| PDF 批注 | 分页 PDF 作为笔记底图、逐页书写 | **已闭环（服务与菜单）**：PDF 分页 PNG 底图导入、每页独立 NotebookPage；服务测试使用可注入渲染器 | Windows/Android 在 PDFium 环境做真实渲染、页码、大文件和内存验收 |
| 文本 | 就地编辑、样式、对齐、自动调整、绑定文字 | **部分具备**：点击输入、失焦/完成提交、文字样式与对齐 | 统一独立画布文本对象，补齐形状绑定文本与编辑状态机 |
| 页面与组织 | Saber 多页笔记、嵌套目录、最近文档、缩略图 | **部分具备**：NotebookPage、文件夹字段、搜索、存储防损坏、缩略图 | 补齐正式文档树界面、拖放移动、最近列表排序、可视缩略图更新和批量管理 |
| 导出与开放格式 | PNG/SVG/剪贴板/工程 JSON / Word / PDF | **部分具备**：PNG、PDF、RTF、工程 JSON、笔画剪贴板 | 实现保真 SVG、完整对象剪贴板、导入导出兼容性测试 |
| 深色模式与反相页面 | Saber 不只切 UI，同时视觉反相笔记、PDF、图片 | **部分具备**：主题基础存在 | 需要独立的“阅读反相”渲染层，不能破坏原始颜色或导出文件 |
| 隐私与同步 | Saber 加密同步；Excalidraw 协作与端到端加密 | **部分具备**：本地 AES-GCM 与恢复密钥基础、存储写入队列/备份恢复 | 云同步、冲突解决、协作、端到端会话密钥均尚未实现，必须作为独立安全项目推进 |
| 图表与高级图元 | Excalidraw 图表、框架、流程图、嵌入元素 | **部分具备**：笔记页图表和形状模型 | 需要统一元素场景后再实现框架、流程图、数据粘贴转图表，避免产生无法编辑的装饰性图标 |

## 分期实施顺序

### P0：手写感与最频繁交互

下一轮优先把当前连续轮廓升级为**采样—实时预览—完成态重建**三段流程；然后把临时高亮笔拆分为独立激光工具，提供可见的尾迹、发光和逐段消退。每个笔刷需有固定、模拟、真实三种压感策略，且通过鼠标、触摸与触控笔输入测试。

### P1：统一对象编辑器

将笔画、文字、图片、形状、连接线抽象为统一可选对象。首先实现多对象选择、组合、锁定、复制粘贴和层级排序，再完成连接线绑定。这一层稳定后，形状库、流程图、框架、图片裁剪和图表才会拥有一致的编辑体验。

### P2：笔记工作流与资料处理

完成正式的文档树、最近记录、页面缩略图、页面排序与复制、PDF 真机验收和全局搜索。SVG 导出、对象剪贴板与阅读反相应随此阶段纳入回归测试。

### P3：同步、协作与加密

仅在本地数据模型、幂等保存与历史恢复持续稳定后，引入可选同步。设计需要覆盖离线队列、版本向量或操作日志、冲突处理、端到端密钥轮换、审计与失效恢复；不能仅添加“同步”图标。

## 验收门槛

每项实施至少应满足以下四项：创建或导入后可立即编辑；撤销/重做语义正确；关闭重开后内容和样式一致；对应自动化测试通过。涉及 PDF、真实笔压、触控与图形性能的条目还需要 Windows 与 Android 真机记录。
