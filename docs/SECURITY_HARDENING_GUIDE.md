# 安全加固使用指南（面向用户）

> 2026-11-15 ｜ 本文说明**已经实现**的安全能力里，哪些需要你动手做一步才真正
> 生效。技术口径见 `SECURITY.md`，本文只讲「怎么做、为什么、不做会怎样」。

---

## 一、审计日志外部锚（推荐做，5 分钟）

### 这是什么

应用会记录安全事件（解锁失败、密钥迁移失败、守卫落盘失败等）到审计日志，
并用**带密钥的哈希链**串起来——改动任何一条都会被发现。

但有一个诚实的边界：**密钥和日志存在同一块磁盘上**。如果有人同时拿到两者
（例如整台电脑被完全控制），他可以把整条链重新算一遍，让日志看起来完好。

**外部锚**就是补这个洞：把日志的"指纹"抄一份到**别的地方**。对方控制不了
那份抄本，所以重算后的日志一定和抄本对不上。

### 怎么做

1. 打开 **设置 → 导出诊断信息**。
2. 报告里会有一段：

   ```
   === 外部锚凭据（请抄存到独立介质：另一设备/打印/密码管理器） ===
   格式版本: 1
   世代号: 3
   条目数: 42
   尾哈希: a1b2c3...（64 个字符）
   导出时刻: 2026-11-15T07:30:00Z
   ```

3. 把这段**存到本机之外**，任选其一：
   - 发到自己的另一台设备（手机备忘录、另一台电脑）
   - 存进密码管理器的备注字段
   - 打印出来放好
4. 建议**每次重要操作后**（改密、批量导入、同步恢复）重新导出一次。

**这段凭据不含任何密钥**，只有哈希结果和计数，所以可以放心外传/打印——
它泄漏了也不会让人解开你的笔记。

### 凭据会"过期"——这是正常的

日志有大小上限，写满后会轮转（旧的一代被覆盖）。如果你抄存的凭据太老，
它记载的那条记录可能已经不在盘上了。这时校验结果是**"无从判定"**，
**不是"通过"也不是"被篡改"**——系统无法区分"记录被改过"和"记录被正常轮转
清理了"，所以不给确定结论。

**建议**：每次重要操作后（改密、批量导入、同步恢复）重新导出一次凭据，
让凭据保持"新鲜"。

### 不做会怎样

不做也能用，审计链本身的防篡改能力照常生效。只是在"整台电脑被完全控制"
这种极端情形下，少了一道独立验证。**日常威胁（偷看文件、改单条日志）不需要
外部锚也能检出。**

## 二、快速解锁（Windows Hello / 指纹）

### 现状与边界

- **Android**：强制生物识别，可信。
- **Windows**：系统有时无法告诉应用"这次到底是不是生物识别验证的"。
  应用采取**保守拒绝**（fail-closed）：无法确认时**不保存**主密钥副本，
  你需要正常输入 PIN。

这是有意的取舍——宁可多输一次 PIN，也不把密钥副本交给一个可能是"纯密码
验证"的通道。

### 建议

- 如果你发现 Windows 上快速解锁"开了但不生效"，这是预期行为，不是故障。
- 想要稳定的快速解锁体验，Android 端更可靠。

## 三、U 盘重置盘（务必保管好）

### 它现在能做什么

U 盘上的 `password_reset_disk.key` 是**忘记密码时的救援钥匙**：
PIN 和 U 盘是"**或**"关系——任一个都能解锁。

### 保管建议

- **不要把 U 盘和电脑长期放在一起**。放在一起等于两个因素退化成一个。
- 建议做**第二把备份 U 盘**，分开存放。
- U 盘丢了：还能用 PIN 正常解锁，但失去救援能力——请尽快重新绑定一把新的。

### 关于"双因素强制模式"

有一种更强的配置是"**与**"关系：必须 PIN **和** U 盘同时具备才能解锁。
好处是别人偷走文件+知道密码也解不开；代价是**U 盘丢了数据永久不可解**。

**该模式目前未实现**，因为不可逆风险需要更完善的备份引导。如果你需要它，
请明确告知——这会是一个独立的功能开发。

## 四、应用层做不到、需要你在系统层做的事

有几项防护**不在应用能力范围内**，说清楚免得误以为已经防住：

| 威胁 | 应用能做的 | 需要你在系统层做的 |
| --- | --- | --- |
| **冷启动攻击**（拔内存条读密钥） | 用完立刻清零密钥内存 | **开启全盘加密**（BitLocker / FileVault / LUKS）+ **禁用休眠** |
| **内存转储**（运行中 dump 进程） | 缩短密钥驻留窗口、回锁即清零 | 锁屏习惯、不给不可信程序管理员权限 |
| **交换文件泄漏**（密钥被写进虚拟内存） | 无法真正阻止（见下） | 全盘加密覆盖交换分区，或禁用交换 |

**为什么应用不做"锁内存防交换"**：Dart 的垃圾回收会**搬移**内存对象，
应用锁住的地址随时会失效——锁了也白锁。要真做需要把密钥全部搬到堆外内存
手动管理，而每次调用加密库又得拷回来，**拷贝本身制造新的残留**。
投入产出比极差，且会给人虚假的安全感。**正确层级是全盘加密。**

## 五、定期自查清单

建议每月或每次重要操作后过一遍：

- [ ] 设置 → 导出诊断信息，看**审计日志完整性**是否"通过"
- [ ] 把外部锚凭据抄存到独立介质（见第一节）
- [ ] 确认 U 盘重置盘在手，且有第二把备份
- [ ] 确认系统全盘加密已开启
- [ ] 确认锁屏/自动锁定设置符合你的使用场景

## 六、看到"异常"怎么办

如果诊断报告显示 **审计日志完整性: 异常（哈希链断裂）**：

1. **先别继续写入重要数据**。
2. 如果你有外部锚凭据，用它比对——能确认是"历史被改写"还是"文件损坏"。
3. 检查磁盘是否有错误（异常断电、坏道也会导致文件损坏，不一定是攻击）。
4. 把诊断报告（已脱敏，不含笔记正文与密钥）发给开发者协助判断。

**注意**："通过"的含义是**在校验范围内未发现篡改**，不等于"绝对完好"——
具体范围与盲区见 `SECURITY.md`「审计链的保证边界」。
