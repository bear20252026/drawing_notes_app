### 缺的部分

1. **`setNotebookKey` 无任何生产调用点**（全仓仅定义处 1 处命中）。

2. **单一 `_sessionKey` 字段**：`setNotebookKey` 是**覆盖**全局字段，不是

3. **无 K_note 持久化**：没有"从笔记本载荷解包 K_note"的生产链路
   （注释里写的 `K_user 包裹 K_note` 信封模式尚未落地）。

## 二、关键风险：AAD 变更是**不可逆**的

这是本方案最重要的一节。

**当前生产媒体的 AAD** = `drawing-notes|media|v1`
**接线后媒体的 AAD** = `drawing-notes|media|v1|<notebookId>`

AES-GCM 的 AAD 参与认证标签计算。**AAD 变了，旧密文就解不开**——不是"降级
兼容"能解决的，必须**解密后重新加密**。

### 由此推出的硬约束

| 约束 | 说明 |
| --- | --- |
| **必须全量重加密** | 每个笔记的每张媒体都要「旧 AAD 解 → 新 AAD 封」 |
| **必须原子提交** | 中途断电/崩溃不能留下"一半旧一半新"的不可解状态 |
| **必须可回滚** | 迁移失败要能退回旧状态，否则用户数据永久损坏 |
| **必须幂等可续** | 大量媒体（可能上千张）迁移要能中断续跑 |
| **必须双读兼容期** | 迁移期间新旧 AAD 并存，读路径要能判别 |

**这五条决定了它不是"加一行 setNotebookKey 调用"，而是一个数据迁移专项。**

## 三、分批方案（建议顺序）

### 批 1：K_note 信封持久化（不改现有媒体）

- 在笔记本加密载荷里增加 `mediaKek` 槽位：随机 32B K_note，用主密钥 MK 包裹
  （复用现有 `VaultKeyService.aeadEncrypt` + 槽位 AAD 模式）。
- 新笔记创建时生成；旧笔记**懒生成**（首次访问时补）。
- **此批不动任何现有媒体密文**，纯增量，可独立验证与回滚。
- 测试：信封往返、MK 换密后 K_note 仍可解、锁定态拒绝。

### 批 2：读路径双 AAD 兼容（只读，零写入）

- 媒体文件头增加 AAD 模式标记（复用现有 `DAN` 魔数 + 版本字节，新增 v2）。
- 读路径：v1 → 旧 AAD（全局密钥）；v2 → 新 AAD（K_note + notebookId）。
- **此批只加读能力，不改写任何文件**——风险极低。
- 测试：v1/v2 混合目录都能正确读出；跨笔记移植 v2 密文必须失败。

### 批 3：写路径切 K_note（新媒体用新格式）

- 解锁笔记时 `setNotebookKey(notebookId, 解包的K_note)`。
- 新写入媒体走 v2；旧媒体保持 v1（双轨，与 VFS 接线同模式）。
- **需要解决单一 `_sessionKey` 的上下文切换**：多笔记并行打开时，
  要么改成按 notebookId 的密钥映射表，要么在每次媒体操作前显式切换上下文。
  **建议前者**（映射表 + 统一清零），后者易漏切换导致 AAD 错配。
- 测试：并行打开两个笔记，各自媒体互不可解；锁定时全部清零。

### 批 4：存量媒体迁移（**高危，需业主批准 + 用户显式确认**）

- 用户主动触发的迁移向导（不在后台静默跑）。
- 逐笔记、逐媒体：旧 AAD 解 → 新 AAD 封 → 原子换入（tmp + flush + rename）。
- 进度可中断续跑；每张媒体迁移前保留原件，全部成功后才清理。
- **迁移前强制备份提示**；失败可回滚。
- 测试：断电注入（中途 kill）、部分失败回滚、幂等重跑、跨笔记隔离。

## 四、工作量与收益评估

| 项 | 评估 |
| --- | --- |
| 批 1-3 工作量 | 中等（信封槽位 + 双读 + 密钥映射表 + 测试） |
| 批 4 工作量 | 大（迁移向导 UI + 原子性 + 回滚 + 断电测试） |
| **安全收益** | **真实**：一笔记密钥泄露不影响其他笔记；媒体密文不可跨笔记移植 |
| 当前替代防护 | 全局会话密钥 + 应用级 AAD（`drawing-notes\|media\|v1`）——已防跨用途交换，但**不防跨笔记** |

**判断**：收益真实且是"每笔记隔离"的最后一块拼图，但**批 4 的不可逆风险
必须业主明确批准**。建议先做批 1-3（纯增量、可回滚），批 4 单独立项。
