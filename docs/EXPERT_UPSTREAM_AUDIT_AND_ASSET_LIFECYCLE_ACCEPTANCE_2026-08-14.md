## 执行结论

本轮完成了对 Excalidraw 和 Saber 的公开源码结构与关键实现模块的深入审计，并将研究转化为一项可验证的真实能力：**绘图文档删除时对离线导入图片执行引用感知、安全边界严格的生命周期清理**。此前绘图文档已经具备独立图片离线副本、按文档串行写入和 `.bak` 恢复，但删除文档时只删除 JSON 和缩略图，受管图片可能成为不可见的磁盘残留。本轮修复后，仅在确认图片是应用受管副本、没有被其他文档引用且主文档可安全解析时才执行回收；用户外部图片路径永不删除。

> **设计准则：数据一致性优先于磁盘清理。** 对于损坏、无法解析或不属于受管目录的任何路径，系统宁可保留资产，也绝不基于不可信数据删除用户文件。

## 上游源码审计结论

### Excalidraw：对象关系的正确性来自明确状态与同批次更新

Excalidraw 将端点操作表示为“建立绑定、显式解除、保持不变”的三态策略；绑定写入时同步维护箭头端点与目标对象的反向关系，解绑时则清理两侧记录。这种双向关系不变量避免了对象删除、目标变换或端点重拖后遗留失效引用。[3]

它的拖动与变换路径还明确区分两类用户意图：移动目标对象时，绑定箭头应重新投影；独立移动绑定箭头时，如绑定目标未被同时选中，则对应端点应解绑，而不应被系统强制吸回旧目标。多对象变换将本轮同时更新对象作为显式集合传递给关系更新层，从而避免多条箭头或群组元素被重复计算。[4] [5]

当前 Flutter 工程已经有归一化锚点、单端自由降级、形状集合快照和撤销/重做。下一步可独立吸收的并非上游源码，而是如下原则：建立由形状集合派生的反向关系索引；用统一选择集合表达多对象事务；将“目标随动”与“连接线直接编辑”设置为不同的端点规则。

| 上游机制 | 当前工程状态 | 独立演进方向 |
|---|---|---|
| 双向绑定关系 | 现有端点单向保存目标 ID 与归一化锚点。 | 增加不持久化、可重建的关系索引与一致性校验。 |
| 多对象共同边界变换 | 形状/图片已可单对象编辑。 | 建立混合对象选择集合、组包围盒和单一历史事务。 |
| 连接线独立移动时解绑 | 创建时绑定、目标变换时投影已实现。 | 实现端点手柄、改绑/解绑和直接移动箭头的意图分流。 |
| 增量历史与协作重放 | 当前单机快照命令稳定可靠。 | 多选成熟后演进到不可变操作批次，避免过早引入协作复杂度。 |

### Saber：流畅手写依赖质量分级、分层合成与资源生命周期

Saber 的笔迹对象为高、低质量多边形和路径建立惰性缓存：活动笔划和高缩放场景使用高质量路径，低缩放时通过抽样、关闭平滑/压力模拟降低渲染成本，停笔后再完成最终优化。[6] 其画布绘制将高亮笔、普通笔、激光、当前笔划、形状识别预览和选择反馈分层；高亮笔按颜色组织合成层，铅笔着色器也按视觉收益阈值启用。[7]

当前工程已经独立实现 `StrokeGeometryCache`、压感归一化、实时预览稀疏化、完笔高保真点列、笔画 outline 渲染以及高亮/激光分层。因此，下一轮的粗笔体验工作应基于 Windows 与 Android 真机帧时间和压感采样进行定量优化，而不是无差别重写现有输入链路。

Saber 对资产生命周期的处理同样提供了可迁移的产品原则：将主笔记、编号资源和预览看作一个移动、删除、导入、恢复的整体，并在外部文件变化或读取暂时失败时保持可恢复行为。[8] 本轮对当前工程的改造正是沿用这一产品原则的独立实现。

## 已独立实现：绘图文档图片资产生命周期闭环

### 行为规格

`StorageService.delete()` 现在先读取待删除文档，以图片引用清单为候选集合；删除主文档、其备份和缩略图后，扫描其余可解析绘图文档的图片引用。只有“候选图片不再被其他文档引用”时才尝试删除。整个流程对路径进行规范化，并要求候选文件的父目录严格等于应用受管的 `document_images/` 目录。

| 场景 | 删除行为 | 安全理由 |
|---|---|---|
| 文档唯一引用一个受管离线图片 | 回收图片副本。 | 没有存活文档可再访问该资源。 |
| 两个文档引用同一受管离线图片 | 删除前一个文档时保留；删除最后一个引用后回收。 | 防止跨文档内容消失。 |
| 文档指向用户外部文件 | 始终保留外部文件。 | 受管目录校验拒绝任意外部路径。 |
| 路径经篡改、相对路径、嵌套目录 | 不回收。 | 严格父目录相等检查抵御路径遍历和误删。 |
| 待删除文档或其他文档无法解析 | 不执行基于该文档的资源清理。 | 无法证明引用关系时采取保守保留策略。 |
| 缩略图或图片删除失败 | 主文档删除仍成功，资源留待后续维护扫描。 | 避免清理失败阻断用户操作。 |

### 回归覆盖

新增 `test/document_asset_lifecycle_test.dart`，对本轮行为进行自动验证。它与原有图片持久化、崩溃恢复、多文档隔离测试共同保证 A/B 文档和受管资源不会在正常生命周期中错位或被误删。

| 回归用例 | 验证内容 |
|---|---|
| 唯一引用清理 | 受管图片、缩略图和 `.bak` 随最后一个文档删除而清理；原始导入文件仍存在。 |
| 共享引用保护 | 删除第一个引用文档后资源继续保留；删除最后一个引用文档后才回收。 |
| 外部路径保护 | 即使 JSON 中记录外部图片路径，删除文档也不会删除该外部文件。 |

## 下一阶段路线

下一阶段应优先扩展近期完成的单对象编辑闭环，而非新增孤立按钮。首先实现**统一多选和原子变换**：形状与图片共用选择集合，框选产生组包围盒，移动/缩放/锁定/删除均使用一条可撤销事务，绑定箭头依据“本次同时选择的目标集合”准确决定投影或脱附。其次实现**箭头端点直接编辑与派生关系索引**，再进入长文档资源预算与真实设备手写性能基准。

| 优先级 | 路线 | 完成定义 |
|---:|---|---|
| P0 | 混合对象多选与组变换 | 框选、混合选择、批量移动/缩放/锁定/删除、取消、撤销/重做和绑定箭头随动均可用。 |
| P0 | 箭头端点编辑与关系索引 | 端点可改绑或解绑；删除和恢复无悬挂 ID；索引可从文档重建并被测试验证。 |
| P1 | 资产维护扫描 | 启动或显式维护时清理可证明无引用的受管孤儿；不扫描或删除外部文件。 |
| P1 | 真实设备手写基准 | Windows 触控笔与 Android 压感设备采集粗笔延迟、采样、帧时间和导出一致性证据。 |
| P2 | 视口缓存预算与导出队列 | 将 PDF 页、图片解码、缩略图和导出任务纳入可取消、可释放、受内存预算约束的生命周期。 |
