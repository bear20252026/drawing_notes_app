# 编辑器交互参考：橡皮擦、选择与墨迹

## 许可证边界

Excalidraw 采用 MIT 许可，可用于理解元素型无限画布、导出与选择交互，但本项目仍采用 Flutter/Dart 的独立实现。Saber 采用 GPL-3.0，只作为行为、产品体验与架构边界参考，**不得复制、移植或改写其源码片段**。[1] [2]

## 可借鉴的行为规范

| 来源 | 已确认行为 | 本项目独立实现策略 |
|---|---|---|
| Excalidraw | 元素型无限画布提供自由绘制、橡皮擦、形状、图像、导出、撤销重做、缩放和平移 | 对独立画布使用对象模型；对象橡皮擦命中笔画/形状后真实删除并进入撤销历史 |
| Excalidraw 橡皮擦讨论 | 将路径中部按点擦除会涉及切分成多对象，且会改变对象生成与选择语义 | 首个版本把“整笔擦除”作为默认对象模式；仅在像素模式使用目标透明合成，不伪装为真实删除 |
| Saber | 采用画布合成保证高亮重叠颜色稳定且不淡化文本 | 延续本项目现有分层高亮合成；临时荧光笔单独管理生命周期，在动画结束时从文档移除 |

## 本轮验收优先级

1. **对象橡皮擦：** 指针接触任意一条笔画/形状时，将整个对象删除；不在画面上绘制黑色假笔画。
2. **像素橡皮擦：** 使用透明合成直接挖空当前图层；实时预览使用透明轮廓，不显示黑色线条。该模式仅影响可见像素，底层对象仍可在未来通过图层管理或撤销恢复。
3. **文字：** 创建、输入、提交、保存、重开必须构成闭环；文本不能只停留在临时 TextField。
4. **圈选：** 必须能够圈中笔画、显示选择边界、移动、缩放、旋转并撤销/重做。
5. **后续专项：** PDF 逐页批注、图片导入、手绘规则形状识别、可消失墨迹均需以真实数据模型、保存和自动测试完成，不可仅增加工具入口。

## PDF 逐页批注依赖核查

`pdfrx` 2.4.7 采用 MIT 许可，官方说明其基于 PDFium，支持 Android 与 Windows，并提供本地文件查看、单页/多页组件、页面覆盖层与页面绘制回调，适合将批注叠加到 PDF 页面的独立工作区。[4] 其 Windows 构建需要启用 Developer Mode，以允许构建过程使用符号链接；这需要在 Windows 真机/打包验收前明确执行。[4]

`pdfx` 同为 MIT，支持 Android、Windows 与本地文件打开，并提供低层页渲染 API；但官方示例提示部分手势查看能力在 Windows 有限制。[5] 因此本项目优先采用 `pdfrx`：PDF 文件保留为资料底图，手写批注使用本项目自己的页面坐标与矢量墨迹模型存储，而不将不可编辑位图当作“批注已完成”。

[4] [pdfrx 官方包页](https://pub.dev/packages/pdfrx) — 版本、许可证、平台支持、PDFium 打包与页面覆盖能力。  
[5] [pdfx 官方包页](https://pub.dev/packages/pdfx) — Windows/Android 渲染 API 与平台限制说明。
