# 混合对象多选与组变换设计

**日期：** 2026-08-14  
**作者：** Manus AI  
**目标：** 在独立绘图文档中，将笔画、形状、图片统一纳入同一选择集合，提供真实可用的框选、移动、等比缩放、锁定守卫、取消、撤销/重做和绑定箭头随动闭环。

## 设计原则

Excalidraw 的对象变换强调“选择集合、受影响的绑定元素和历史提交必须视为同一事务”；当前工程的单形状变换也已采用形状集合快照以保证节点与箭头不会在撤销后失步。本轮将这一原则推广到混合对象集合：一次用户手势只形成一条历史命令，取消手势严格恢复按下前状态，绘制过程只触发画布局部刷新。[1]

> **选择并不等于可变换。** 锁定形状和图片可以被选中并通过琥珀色状态向用户说明保护状态，但不会参与移动或缩放。这样既可批量审视对象，也不会意外扰动资料底图或固定节点。

| 选择类别 | 持久身份 | 命中规则 | 可参与移动/缩放 | 参与包围盒 |
|---|---|---|---|---|
| 笔画 | 当前图层中的索引 | 点落入/线段穿过框选或套索区域。 | 是。 | 是。 |
| 形状 | `PageShapeItem.id` | 与选区相交；点击时按 z-order 命中最上层。 | 未锁定时是。 | 是；箭头使用投影后的可见端点。 |
| 图片 | `DocumentImageItem.id` | 与选区相交；点击时按 z-order 命中最上层。 | 未锁定时是。 | 是。 |

## 原子事务与恢复模型

混合变换会同时改动图层笔画、形状集合和图片集合，因此不能复用三个相互独立的历史命令。新命令保存三个集合的深度快照。撤销与重做通过同一恢复入口按“图层 → 形状关系图 → 图片”的顺序还原，并校验当前选择 ID 是否仍存在。

| 阶段 | 行为 | 历史状态 |
|---|---|---|
| 框选/点击 | 仅更新运行时选择 ID/索引，不改写文档。 | 无。 |
| 首次有效移动或缩放 | 记录混合深度快照。 | 暂不入栈。 |
| 拖动中 | 更新对象并仅 `tickFrame()`，避免重建工具栏。 | 仍是同一事务。 |
| 结束手势 | 若快照与当前状态不同，压入一条混合快照命令。 | 一条命令。 |
| 取消手势 | 直接恢复开始快照。 | 不产生命令。 |
| 撤销/重做 | 恢复三类对象和箭头关系。 | 没有对象间中间态。 |

## 绑定箭头在组变换中的规则

绑定关系是持久化模型，投影端点是可见几何。批量变换必须先处理被选中的可绑定节点，再处理选中箭头的自由端，最后统一重投影所有绑定箭头。

| 场景 | 结果 |
|---|---|
| 节点被选择，箭头未选择 | 绑定端点按归一化锚点重投影，箭头自动随节点变化。 |
| 节点和箭头都被选择 | 绑定端点随节点；箭头的自由端按组变换；整条连接线保持连续。 |
| 仅选择自由箭头 | 两端按照组变换。 |
| 仅选择已绑定箭头 | 绑定关系优先，已绑定端点维持在目标上；本轮不隐式解绑，避免拖动导致数据关系丢失。 |
| 目标锁定 | 目标不参加变换；依赖它的箭头保持原投影。 |
| 删除/端点重绑 | 不属于本轮组变换；继续由现有单对象删除和后续端点编辑闭环处理。 |

## UI 与性能边界

在单个形状或图片被点击时，保留现有专属边框与手柄。选择多于一个对象时，在画布上额外渲染统一的蓝色组包围盒；若集合包含锁定对象，包围盒显示琥珀色提示。对象集的拖动和缩放仍使用现有帧通知通道，滑块/手势结束时才通知低频 UI 并保存。

本轮不实现跨图层笔画选择、旋转、分组持久化或端点直接重绑。它们需要单独的数据模型和交互规格，不能以“多选”名义半实现。

## 回归验收

测试至少覆盖混合矩形/套索命中、组包围盒、移动后绑定箭头随目标重投影、锁定守卫、缩放、取消恢复和一条命令的撤销/重做。每项测试只验证控制器真实数据，而非按钮可见性。
