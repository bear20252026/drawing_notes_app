本轮最需要优先处理的两个真实数据风险（已人工复核代码属实）：
① 日程待办：读取失败被静默成空表，而「新增」是「全量读 → 加一条 → 整文件覆写」——一旦读取失败，添加一条待办会永久清空其余全部待办且无任何提示。
② 画板元素菜单：分组 / 设置链接 / 置顶 / 置底 4 个动作只挂在右键上，触屏长按与键盘命令面板均无入口——触屏与键盘用户永久拿不到。

高严重级 8 项

高 待办读取失败静默返回空表

lib/features/schedule/infrastructure/schedule_event_store.dart:57-58

catch (_) { return const []; }——文件损坏或 JSON 解码失败被吞成「没有待办」，用户打开日程发现全没了，零提示、零审计日志。

修法：区分「文件不存在」（返回空）与「读取/解码失败」（抛异常 + AuditLogger.log('schedule.load', success:false)），页面捕获后显示「待办读取失败」并保留原 UI。

高 读取失败后新增会整文件覆写 → 永久清空全部待办

lib/features/schedule/infrastructure/schedule_event_store.dart:92-93

final events = [...await loadAll(), event]; await _writeAll(events);——上一条的静默空表 + 这里整文件覆写 = 添加一条待办即清空其余全部，无提示。这是本轮唯一会「用户主动操作导致数据全丢」的路径。

修法：loadAll 失败时禁止写入并显式报错；_writeAll 加 try/catch 清理 tmp 后 rethrow。

高 待办增删改是无锁 read-modify-write，重入丢更新

schedule_event_store.dart:92 / 99 / 110

三个方法都是「全量读 → 内存改 → 全量写」，无去重/加锁/序列号。连点两次添加，或添加与打勾并发，后写快照覆盖前一个。

修法：照抄 note_block_doc_store.dart:134 的 _enqueue 按 id 串行化。

高 事务回滚失败只 print，画板停在半应用状态

lib/features/drawing/application/document_transaction.dart:64-68

批量命令 redo 中途失败时回滚再失败 → 画布停在「部分生效」的不一致状态，用户只看到原始异常，不知道撤销栈已不可信；同时是生产代码 print 残留。

修法：回滚失败抛 TransactionRollbackException（至少也要 AuditLogger + 提示「部分操作已回滚，请检查画布」），print 换成调试日志。

高 画板元素上下文菜单仅右键可达（触屏 + 键盘双盲）

editor_page_overlays.dart:102 · editor_page_text_overlays.dart:179

菜单含 7 个动作，其中分组 / 设置链接 / 置顶 / 置底 4 个在全库无第二入口：无长按、无 ⋮ 按钮，命令注册表（editor_page_commands.dart:12-84）也未注册，Ctrl+K 命令面板无兜底。副证：弹菜单位置硬编码 RelativeRect.fromLTRB(100,100,0,0)，连鼠标用户都不是在指针处弹出。

修法：补 onLongPressStart 用 details.globalPosition 定位（照抄 all_doc_row.dart:60 写法），并把 4 个动作注册进 CommandRegistry。

高 画布缩放/旋转/裁剪/文本框手柄通通 10×10，触屏点不中

resize_handles.dart:37,84-86 · editor_page_overlays.dart:155-157 · editor_page_drag_ops.dart:394-396 · editor_page_text_overlays.dart:336-338

手指接触面约 40px，10px 命中率极低——这是画板核心操作，触屏主用设备上体验直接打折。

修法：视觉保持 10px，用 SizedBox(44,44) + Center 扩热区（项目已有 all_doc_row.dart:137 的同类修法可复用）。

高 删除笔记本遗留 .bak 孤儿文件（删不干净 + 数据可恢复）

lib/features/notes/infrastructure/notebook_storage.dart:237（每次保存 copy 出 .bak）· :338-364（delete 未清理）

其余三个存储删除时都清了 .bak（storage_service.dart:699-702、edgeless_doc_store.dart:128-133、note_block_doc_store.dart:502-509），唯独笔记本没有——用户「删除」后上一版完整内容仍永久躺在盘上，且 load() 在 :259-262 会优先读它。既是隐私风险也是行为不一致。

修法：delete() 内补 File('${file.path}.bak').delete()（try/catch 吞异常），与另三处对齐。

高 保险库槽位临时文件残留，含被包装的主密钥

lib/core/security/vault_key_service.dart:513-515

tmp.writeAsString(doc) → rename，无 try/catch。doc 含 slots[].salt 与 slots[].wrapped；Windows 上 rename 覆盖已存在文件会抛异常，此时 .tmp 永久留在数据目录，成为密钥材料残留面。

修法：套用 encrypted_vault.dart:135-148 已写对的 _atomicWrite 模式——catch 内删除 tmp 后 rethrow。
