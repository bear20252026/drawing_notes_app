# 同步 E2E 密钥派生（PBKDF2 → Argon2id）迁移评估

> 来源：全量审计 2026-09-26 #39（P3）。**本文档仅为评估，未改动任何代码。**
> 审计结论原文：同步 E2E 密钥派生维持 PBKDF2 600k 而非 Argon2id，强度弱于
> 新槽位基线，建议评估带版本标记的迁移路径。

## 一、现状

| 项 | 值 |
|---|---|
| 位置 | `lib/core/sync/sync_cipher.dart` `deriveMasterKey` |
| 算法 | PBKDF2-HMAC-SHA256，600,000 次迭代（OWASP 2023/2026 推荐档） |
| 维持理由（代码注释） | 批B：同步格式跨设备互操作，KDF 与既有密文耦合 |
| 本地文件加密基线（对照） | Argon2id m=64MiB / t=2 / p=2（新槽位）+ PBKDF2 600k（v1→v5 演进兼容） |
| 派生性能设施 | KekSessionCache（会话缓存 + isolate 后台派生）已接入，无 UI 卡顿 |

## 二、威胁模型：差距有多大

E2E 同步密文的爆破面在 **WebDAV 服务器侧副本**（攻击者拿到全部密文 +
盐 + 迭代参数后离线爆破用户密码）。

- PBKDF2-HMAC-SHA256 是**纯计算硬度**：GPU（如 RTX 4090 集群）对
  SHA256 的吞吐使 600k 迭代的实耗约毫秒级/口令，单卡每天可试数十亿级
  口令组合（字典 + 规则变种场景）。
- Argon2id 的 **64 MiB 内存硬度**使 GPU 每核并行度被显存钳制，同硬件
  吞吐下降 2–3 个数量级；这正是本地加密新槽位选它的原因。
- 实际风险还取决于用户密码熵：同步主密码若为高熵随机串，PBKDF2 600k
  在可预见期内不可爆破；若为低熵人记忆口令，Argon2id 的边际收益显著。

**结论：差距真实存在，但威胁兑现依赖「服务器副本泄露 + 低熵口令」两个
条件叠加，非紧急漏洞。**

## 三、迁移路径（带版本标记）

与块文档加密 v1→v5 演进（`encryption_version_test`、KDF 迁移套件先例）
同一模式，项目内已有成熟双读窗口经验。

### 方案 A（推荐）：信封版本化 + 事件触发增量迁移

1. **版本标记**：同步信封新增 `kdf: 'argon2id' | 'pbkdf2'`（或整数版本）
   字段——旧信封无该字段 = pbkdf2（fail-open 读兼容）。
2. **双读窗口**：解密侧按标记分派 KDF（`KdfParams.argon2id(...)`
   / `KdfParams.pbkdf2(600000)`），`KekSessionCache` 已按参数族分桶缓存，
   零改动。
3. **迁移触发点**：只在**用户主动事件**重绕——改密、重新配对、新设备
   首次绑定。不做后台静默迁移（多端并发重绕会制造密文版本漂移与冲突
   面扩大，`sync_conflict` 机制不为 KDF 设计）。
4. **收敛**：发布若干版本后可评估强制升级（拒绝写旧格式），或长期保持
   双读（推荐后者——同步密文天然长寿且多端）。

### 方案 B（不推荐）：新设备直接 Argon2id、旧设备锁死

配对即分叉，互操作矩阵复杂化（A↔B 跨版本配对/改密组合爆炸），收益不
比方案 A 高。

### 风险与对策

| 风险 | 对策 |
|---|---|
| 多端并发重绕竞态 | 只在用户主动事件触发 + 现有乐观锁/冲突检测 |
| 旧客户端读到新格式 | 版本字段缺失语义 = 旧格式，新格式旧客户端解不开属预期（需发布协调：先发支持版，再切换写侧） |
| Argon2id 64MiB 在低端安卓的派生时延 | 已有 isolate + 会话缓存；首次绑定可接受 1–2s |
| 真 KDF 测试矩阵膨胀 | @Tags(['kdf']) 套件已分流独占串行；新增跨版本往返用例 2–3 个 |

### 工作量估计

代码约 2–3 天（信封版本字段 + 分派 + 事件重绕 + 测试），发布协调另计。

## 四、结论与建议

1. **可迁移、非紧急**：维持 PBKDF2 600k 在「服务器副本泄露 + 低熵口令」
   同时发生时才构成实质削弱；当前 OWASP 合规。
2. **建议**：采纳方案 A，在下次触及同步加密域（改密流程重构、配对协议
   升级）时**顺车**实施，不单独立项；实施时按铁律走真 KDF 测试
   （@Timeout 3min + @Tags kdf）。
3. 若决定不迁移，建议在 `sync_cipher.dart` 注释中把「为何维持 PBKDF2」
   的威胁模型结论（本文第二节）补全，替代现有的单句批B 注。
