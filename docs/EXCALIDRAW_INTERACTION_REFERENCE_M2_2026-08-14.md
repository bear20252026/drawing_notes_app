# Excalidraw 交互参考：M2 书写、形状与工作区分层

本记录仅提取可公开验证的产品与架构原则，用于本项目的独立 Flutter 实现；不复制 Excalidraw 的 TypeScript 源码。

## 1. 本轮采用的参考原则

| 领域 | Excalidraw 公开资料中的做法 | 本项目独立实现决策 |
|---|---|---|
| 自由书写 | 自由绘制元素保留点列、压感数组与是否模拟压感；绘制时从输入点生成封闭的笔触轮廓 | 粗笔不再仅以中心线和圆形端点绘制；将建立基于连续路径/轮廓的粗笔渲染，保留真实或模拟压感并避免离散大圆点 |
| 书写性能 | 在书写中避免重复进行昂贵的全元素边界计算，使用点列近似边界并缓存昂贵几何 | 保留当前实时稀疏预览与收笔精修机制，并将渲染几何缓存为每笔独立数据，避免每帧重新构造全部粗笔路径 |
| 形状模型 | 矩形、椭圆、菱形等均为具有位置、尺寸和样式的独立元素；线和箭头是带点列的线性元素 | 形状工具将以“按下创建草稿、移动更新尺寸、抬起提交元素”的单一生命周期工作，不能只在抬起时创建固定尺寸图标对象 |
| 无限画布 | 白板以无限画布、缩放和平移为核心工作区语义 | 绘图模式移除固定纸张的编辑限制，维持坐标空间与可见区域变换；笔记模式保留分页纸张语义 |
| 文档与绘图区分 | 白板元素与文档类文本/容器拥有不同的模型与操作语义 | 将建立显式工作区类型：绘图为无限画布，笔记为分页文档，并分别控制创建、布局和导出流程 |

## 2. 可验证来源

Excalidraw 公开仓库将其定位为带无限画布、自由绘制、几何形状、撤销重做、缩放和平移的白板产品；元素文档说明了形状、线性元素与压感自由绘制元素的独立模型。其自由绘制改进讨论说明了从输入点列生成笔触轮廓、缓存性能敏感几何以及在书写过程中避免昂贵操作的工程思路。

- https://github.com/excalidraw/excalidraw
- https://excalidraw-excalidraw.mintlify.app/concepts/elements
- https://github.com/excalidraw/excalidraw/issues/3500
