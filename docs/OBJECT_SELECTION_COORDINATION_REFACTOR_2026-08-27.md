# 对象编辑选择协调重构

**作者：Manus AI**  
**日期：2026-08-27**  
**目标分支：`refactor/object-selection-coordination`**

## 1. 改造背景

`DocumentObjectEditingSession` 负责独立画布中图片、形状及混合对象的选择、变换和撤销协调。会话原先直接维护两组可变 id 集合和两个活动 id，并在图片命中、形状命中、多对象框选、清空、删除和快照恢复等路径中重复修改这些字段。虽然每条路径都能工作，但“集合与活动 id 必须一致”“跨类型选择必须互斥”“快照恢复后不得保留已删除 id”等不变量分散在多处，未来扩展连接线或更多对象类型时容易遗漏修正。

> 本批次将会话级对象选择暂态收口为 `DocumentObjectEditingSession` 的私有协调值对象。它不替代既有 `DrawingImagesNotifier` / `DrawingShapesNotifier`，也不向 UI 暴露可写状态；会话仍是独立画布对象编辑的唯一运行时写入者。

| 现状问题 | 风险 | 本批次处理 |
|---|---|---|
| 两类对象选择集合与活动 id 由多条命令直接写入 | 单选/多选/恢复后可能出现陈旧活动 id | 用单一状态对象维护集合和活动 id 的协同更新 |
| 选择清理逻辑分布在恢复和删除路径 | 新增对象类型时容易忘记修正 | 以统一的 `retainExisting` 机制处理恢复后的存活 id |
| 图片和形状命中逻辑各自写入另一类型清理 | 互斥规则难以统一审阅 | 用显式的单类型选择与混合选择 API 编码规则 |
| 应用层目录达到 40 文件上限 | 新增 helper 文件会触发目录门禁 | 将私有、会话专属值对象放在所属会话文件中，不增加文件数量 |

## 2. 目标职责

| 组件 | 责任 | 非责任 |
|---|---|---|
| 私有 `_DocumentObjectSelectionState` | 存储形状/图片 id 集合和活动 id；负责单类型选择、混合选择、清空、删除类型选择及存活修正 | 命中测试、文档变更、撤销、缓存、通知、Widget、I/O |
| `DocumentObjectEditingSession` | 调用几何服务命中对象；执行对象变换、快照、命令提交、图层失效与宿主通知 | 分散维护选择字段的细节 |
| `DocumentObjectEditingHost` | 保持笔画选择、历史、缓存和 UI 通知的实际实现 | 持有对象选择暂态 |
| Riverpod 可见选择 Notifier | 继续仅暴露不可变 UI 状态，不写入本会话运行时状态 | 与会话形成第二写入源 |

## 3. 行为不变量

1. 命中图片时，形状集合与活动形状必须清空；命中形状时，图片集合与活动图片必须清空；二者都清除笔画选择。
2. 混合选择可同时包含形状和图片；仅当某类型刚好选择一个 id 时，才保留对应活动 id。
3. 清除单一类型选择不应隐式清除另一类型或笔画选择；清除混合选择必须清除笔画、形状和图片选择。
4. 单对象删除必须移除对应活动 id；混合删除在快照命令生成前清空混合选择。
5. 恢复混合对象快照后，选择集合仅保留仍存在的形状/图片 id；活动 id 必须属于保留集合，否则设为 `null`。
6. 本批次不改变变换手势的快照边界、撤销命令类型、`invalidateLayer`、缓存重建、`rebuildAll`、通知次数或调用顺序。

## 4. 验收方式

| 验收项 | 验证方式 |
|---|---|
| 图片/形状命中选择保持跨类型互斥 | 会话直接测试 |
| 混合选择同时保留两类型并仅在单选时激活 | 会话直接测试 |
| 删除与快照恢复不留下陈旧选择 id | 现有恢复回归测试补强 |
| 锁定、变换和撤销行为不变 | 现有对象编辑、图片编辑、形状编辑和混合对象回归测试 |
| 不增加 application 目录文件 | 文件计数与远程行数门禁 |
| 无跨层依赖或静态分析问题 | `flutter analyze`、边界检查、全量测试 |

## 5. 非目标

本批次不改变 `DrawingController` 的公开委托 API，不将会话状态接入 Riverpod，不改动对象命中几何、锁定语义、历史命令格式或渲染缓存实现。将对象编辑命令进一步划分为独立应用服务需要先设计跨会话事务与撤销契约，应另行评审。
