# 专家级对象关系与资料性能优先级矩阵

**日期：** 2026-08-14  
**对标基线：** Excalidraw（MIT）与 Saber（GPL-3.0，仅行为与架构研究）  
**适用工程：** `drawing_notes_app`（Flutter / Windows / Android）

## 决策方法

本矩阵不以“图标数量”衡量产品成熟度，而按四个维度排序：**高频使用价值、数据正确性风险、现有架构依赖、自动化验收可行性**。只有能形成“创建—编辑—撤销—保存—重开—导出”的能力才进入近期实施。

| 优先级 | 能力 | 价值 | 架构前置 | 主要风险 | 可验证完成标准 |
|---|---|---:|---|---|---|
| P0 | 独立图片对象编辑 | 已交付 | 文档图片模型、资源副本、命令栈 | 图片资源引用/历史遗漏 | 选择、拖动、缩放、删除、取消、撤销重做、重开、导出 |
| P1 | 连接线端点绑定 | 极高 | 稳定对象 ID、形状 bounds、命令事务 | 移动后箭头漂移、删除悬挂引用 | 两端绑定；移动/缩放/删除后关系正确；一手势一历史项 |
| P1 | 对象锁定与层级操作 | 高 | 统一对象适配器的最小字段 | 锁定只在 UI 生效、导出差异 | 锁定对象拒绝命中变换；置顶/置底保存重开一致 |
| P1 | 图片资源运行时回收 | 高 | `assetId`/文件路径、可见页面观察 | 大 PDF/图片内存累积 | 关闭文档释放；删除不误删可撤销资源；邻页预加载受限 |
| P2 | 分组与多对象变换 | 高 | 通用 bounds/transform、命令快照 | 关系对象部分移动 | 任意对象混选后平移/缩放；撤销重做一致 |
| P2 | 形状容器与绑定文字 | 中高 | 文字对象协议、形状尺寸通知 | 文本折行/裁剪不一致 | 形状缩放时标签稳定、保存导出一致 |
| P2 | 选择命中基于呈现几何 | 中高 | 平滑中心线/轮廓缓存 | 稀疏点列与视觉不一致 | 稀疏粗笔、曲线边缘均可预期选中 |
| P3 | 分数层级键 | 中 | 对象协议、迁移格式 | 旧文档排序迁移与并发调试 | 本地排序兼容；同层插入稳定；无协作时不可影响性能 |
| P3 | PDF 原件跨页共享缓存 | 中 | 文档资产库、页可见性 | 原生资源泄漏、平台差异 | 100 页 PDF 的相邻页浏览内存受限，关闭释放句柄 |
| P4 | 端到端加密同步 | 高但不可抢跑 | 版本/墓碑/顺序、恢复/冲突协议 | 误导用户隐私、数据丢失 | 多设备断网/冲突/删除/密钥丢失演练全部通过 |

## 立即实施建议

本轮推荐实施 **P1：连接线端点绑定的最小正确内核**，而不急于实现复杂肘形路线或完整协作。原因是当前项目已经有 `PageShapeItem`、独立画布形状、页面连接线和对象级图片选择；端点绑定能直接让流程图从“画线”升级为“可编辑关系图”，同时验证统一对象 ID、几何变化、命令事务和删除策略。

第一版只应支持独立绘图文档中的直线/箭头连接两个可绑定形状，采用目标矩形的归一化锚点 (`0..1`) 保存端点。拖动目标形状时，连接线端点重新投影；删除目标时，连接线自动断开为当前绝对位置；复制目标时不自动复制外部关系。该范围避免了未完成的文本容器、分组和协作逻辑，却已经覆盖关系图内核的关键正确性。

> Excalidraw 的绑定设计表明，连接关系应以对象 ID 与局部锚点表达，在几何变化时由统一维护入口重投影；Saber 的经验表明，持续手写和资料阅读的帧预算不得被低频对象操作破坏。[1] [2]

## 资源性能实施护栏

| 护栏 | 短期独立措施 | 触发条件 |
|---|---|---|
| 运行时解码 | 所有 `ui.Image` 归控制器/资产缓存管理，`dispose` 必须释放 | 关闭文档、替换资源、缓存驱逐 |
| PDF 句柄 | 一份原始 PDF 一个惰性文档句柄；页面位图按可见性加载 | 页面切换、导入多页资料、应用转后台 |
| 缓存预算 | 只预加载当前页前后邻页；无限画布按可见对象加载 | 内存阈值、缩放越界、快速翻页 |
| 保存安全 | 写入时短暂冻结资源驱逐；原子文件完成后再释放 | 导入、自动保存、导出 |
| 导出保真 | 导出走原始对象和资源，绝不依赖低清缩略图或反相显示 | PNG、PDF、RTF/Word 导出 |
