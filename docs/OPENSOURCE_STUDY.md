# 开源软件全量学习报告（OPENSOURCE STUDY）

> 学习日期：2026-08-13
> 学习范围：用户提供的 15 个开源项目（8 笔记软件 + 7 办公套件）
> 学习方式：README/技术栈/架构目录批量调研 + 关键源码深度研读（Joplin、QOwnNotes、Memos、Umo Editor、ONLYOFFICE 等）
> 学习目标：提炼可借鉴点，落地到本项目（绘图+笔记 App，Flutter，保持现有 UI 设计不变）

## 一、笔记软件类（8 个）

### 1. Lokus（Rust + Tauri，本地优先）
- **技术栈**：Rust + Tauri（≈50MB 内存，远低于 Electron 300MB+）
- **可借鉴点**：
  - ✅ 本地优先 + 标准 Markdown 文件存储（数据永不锁定）——与本项目"纯本地 JSON 工程文件"理念一致
  - ✅ 富文本 + Markdown 实时预览双模式
  - ✅ Wiki 链接 `[[自动补全]]`、LaTeX 公式（KaTeX）、100+ 语言语法高亮
  - ✅ 无限画布（TLDraw）、图谱视图（2D/3D）、数据库视图
  - ✅ 键盘优先设计（~30 个斜杠命令）、模板系统（90+ 特性）
- **落地建议**：轻量渲染架构、本地优先存储（已具备）；斜杠命令可作为后续文字工具增强

### 2. Trilium Notes（层级知识库，33.3k⭐）
- **可借鉴点**：
  - ✅ 任意深度层级树；单条笔记可克隆到多个位置
  - ✅ 内置脚本自动化（笔记可作为代码执行）
  - ✅ 加密与自建服务器同步
- **落地建议**：层级/克隆机制适合大型知识库，与本项目"画板笔记"定位不同，仅作架构参考

### 3. Joplin（52.4k⭐，Evernote 替代品）—— 已深度研读源码
- **源码研读**（`NoteEditor.tsx` 33429 字节）：
  - ✅ **多编辑器后端可插拔架构**：TinyMCE（富文本）/ CodeMirror 5/6（Markdown）/ PlainEditor（纯文本）/ WhiteboardEditor（白板），通过 `usePluginEditorView` 动态切换——本项目可借鉴"工具视图可插拔"思想
  - ✅ **调度保存**（`useScheduleSaveCallbacks`）：变更后调度保存回调——与本项目 800ms 防抖自动保存机制一致（已验证正确）
  - ✅ **命令服务架构**（`CommandService` + `ToolbarButtonUtils`）：所有操作注册为命令，工具栏按钮由命令驱动——便于快捷键/菜单/工具栏统一管理
  - ✅ **搜索条**（`NoteSearchBar`）、**状态栏**（`StatusBar`）、标题栏（`NoteTitleBar`）分层 UI
  - ✅ 离线优先 + 端到端加密 + OCR + 全平台
- **落地建议**：**状态栏信息显示**（缩放/工具状态）与**命令服务模式**最值得借鉴

### 4. Relatum（无限画布，Windows，本地优先）
- **可借鉴点**：
  - ✅ 无限自由画布：节点自由创建/拖动/连线，自定义颜色/大小/形状/圆角/透明度/字重/字号/对齐
  - ✅ 一键思维导图排版（多种布局：左右/放射/均衡）、分支配色、层级尺寸
  - ✅ Obsidian Canvas `nodes + edges` 结构兼容
  - ✅ 节点支持手写、文字框、色块、装饰图案
  - ✅ 专注学习工具：番茄钟、每日任务、学习看板、间隔复习
  - ✅ 小地图（画布导航）、关系图谱、PNG 导出
- **落地建议**：**小地图**（画布放大后导航定位）与**节点样式丰富化**（圆角/透明度/对齐）最值得借鉴

### 5. Memos（MIT，自托管 Google Keep 风格）—— 已调研架构
- **可借鉴点**：
  - ✅ 时间线优先界面：打开即写、写完即走（极简输入体验）
  - ✅ Markdown 原生、单 Go 二进制/Docker 部署、SQLite/MySQL/PostgreSQL
  - ✅ REST + gRPC API、无遥测
- **落地建议**：**极简输入理念**已通过"就地编辑（点击页面直接打字）"落地；时间线式笔记列表可作为首页增强

### 6. QOwnNotes（GPL，Markdown + 待办）—— 已深度研读源码
- **源码研读**（`main.cpp`）：
  - ✅ **多语言翻译系统**：`loadTranslations` 支持 13 个翻译文件位置 + 运行时语言切换
  - ✅ **单实例应用**（`SingleApplication`）：重复启动聚焦已有窗口
  - ✅ **系统深色模式监听**（`QStyleHints::colorSchemeChanged`）：跟随系统明暗切换
  - ✅ 纯文本 Markdown 文件存储 + Nextcloud/ownCloud 同步、待办清单、快捷键体系
- **落地建议**：**单实例**（Windows 二次启动聚焦现有窗口）与**系统深色联动**最值得借鉴

### 7. Notes（nuttyartist，C++/Qt 原生）—— 已调研
- **可借鉴点**：
  - ✅ Markdown 任务转看板（Kanban）
  - ✅ 嵌套文件夹 + 全局标签双组织维度
  - ✅ 多主题（浅色/深色/棕褐色）、Feed 视图（多笔记连续阅读）
  - ✅ 全局热键召唤（Win+Shift+N）、**纯键盘操作**、快捷键文档化
- **落地建议**：**快捷键文档化**与**标签组织**可作为后续增强

### 8. nb（AGPL，命令行笔记 + Git 版本控制）—— 已调研
- **可借鉴点**：
  - ✅ 纯文本存储 + **Git 版本控制与同步**（每次修改自动提交）
  - ✅ 加密笔记、过滤/置顶/标签/搜索、wiki 链接、待办任务
  - ✅ Pandoc 导入导出多格式、插件化
- **落地建议**：**版本历史**（基于自动保存快照回溯）已在后续方向清单中；Git 同步思想用于未来云同步设计

## 二、办公套件类（7 个）

### 9. ONLYOFFICE Personal（AGPL，WASM 本地化办公）—— 已调研架构
- **技术栈**：HTML5 + JS + x2t.wasm（文档转换引擎）+ ONLYOFFICE Document Server WASM 版
- **可借鉴点**：
  - ✅ **完全本地化**：无服务器、数据不出本机（WASM）——与本项目"纯本地"路线一致
  - ✅ 完整办公功能：文档/表格/演示/PDF 编辑、公式、动画
  - ✅ 格式兼容：.docx/.xlsx/.pptx + PDF 批注表单
  - ✅ 熟悉的办公工具栏布局（学习成本低）
- **落地建议**：**工具栏分组布局**（文件/编辑/格式等分区）与 PDF 批注理念可参考

### 10. Umo Editor（MIT，Vue3 + Tiptap3，类 Word）—— 已调研架构
- **技术栈**：Vue3 + Tiptap3（ProseMirror 封装）、分页模式 + 普通 Web 模式
- **可借鉴点**：
  - ✅ 类 Word 编辑体验：分页渲染、Markdown 语法、富文本、多节点插入
  - ✅ 页面样式设置、导出打印、自定义扩展、多语言、暗色主题
  - ✅ 移动端独立设计（触摸优先、保存状态机、导航守卫、历史）
  - ✅ 私有化部署、零配置集成
- **落地建议**：**分页渲染**（本项目为单页画布，可参考其纸张概念）与**节点插入体系**

### 11. DzzOffice（PHP，类 Google 套件）
- **可借鉴点**：多云存储、在线文档、团队协作、私有化部署
- **落地建议**：协作/云存储属后续阶段方向，与本地优先定位互补

### 12. GenOffice（Apache 2.0，AI 原生办公）
- **可借鉴点**：
  - ✅ AI 编辑即一等工作流（块级编辑 + 快照 + diff）
  - ✅ 真实格式兼容（.docx 字节级保真、Rust .xlsx 侧车）
  - ✅ 六合一：文档/表格/演示/PDF/Markdown 编辑器共享同一引擎层
- **落地建议**：**AI 块级编辑 + 快照 diff** 是 AI 阶段的优秀设计（本项目 AI 为后续阶段）

### 13. AbiWord（GPL，轻量 C++ 文字处理）
- **可借鉴点**：轻量跨平台、文字处理器标准功能集
- **落地建议**：文字属性（字号/颜色/对齐/字重）为标配——本项目已落地字号/颜色

### 14. Euro-Office（ONLYOFFICE 开源分支）
- **可借鉴点**：微软 Office 格式 + 开放文档格式双兼容、欧洲企业联合维护
- **落地建议**：格式兼容策略参考（.docx 保真编辑）

### 15. Joeffice（Apache，纯 Java 办公套件）
- **技术栈**：NetBeans 平台 + Apache POI + H2，模块化（文字/表格/演示/绘图/数据库）
- **可借鉴点**：**模块化架构**（Word/Excel/PPT/绘图各自独立模块共享平台）
- **落地建议**：模块化思想——本项目已按 UI/引擎/存储分层，架构同源

## 四、结论

15 个项目共同验证了本项目路线的正确性：
1. **本地优先/数据自主** 是共识（Lokus/Joplin/Memos/ONLYOFFICE/Relatum 全部强调）；
2. **低延迟渲染与跟手感** 是第一评判标准（Lokus 用 Rust/Tauri 省内存、Joplin 多编辑器后端）；
3. **键盘快捷键与状态信息透明** 是桌面软件基本盘（Notes/QOwnNotes/Joplin）；
4. **模块化分层架构** 是长期演进基础（Joeffice/Joplin/GenOffice 均模块化）。

下一阶段按 P1 优先级落地"状态栏"与"纸张模板"两项新功能（保持 UI 布局不变）。

## 六、深度评价：15 个开源方案的优点挖掘与评级（2026-08 补充）

> 本节超越"可借鉴点清单"，从**架构、许可、生态、技术取舍、局限、适用场景**六个维度
> 对每个方案给出深度评价。评级：A=优秀成熟 / B=良好可用 / C=有亮点但有明显短板。

### 笔记软件类

#### 1. Lokus（Rust + Tauri，Fair Source 1.0）—— 评级 B+
**深层优点**
- **技术架构**：Rust 内存安全 + Tauri 复用系统 WebView（不打包 Chromium），二进制小、内存仅 ~50MB，是 Electron 类应用的 1/6；双向链接/图谱/数据库视图集成度极高。
- **取舍**：无限画布（TLDraw）+ Markdown 双轨，兼容 Obsidian 语法（`[[wiki]]`、KaTeX、Mermaid）。
- **许可注意**：Fair Source 1.0 **不是严格意义开源**（延迟开源、使用受限），商业采用需评估。

#### 2. Trilium Notes（TriliumNext 社区版，AGPL）—— 评级 A-
**深层优点**
- **知识组织模型是行业标杆**：任意深度层级树 + 笔记克隆（一处修改多端生效，非复制粘贴）——这是"第二大脑"类产品最好的信息架构。
- **脚本即扩展**：笔记内可直接写 JavaScript 脚本操作整个库，可编程性远超同类。
- **前后端分离**（Node server + Web 前端），便于自建同步与 API 集成。

#### 3. Joplin（AGPL，52k★）—— 评级 A
**深层优点**
- **端到端加密同步**：Evernote 替代品中唯一把"加密"做透的；数据用标准 Markdown + 资源目录存储，可移植性强。
- **插件生态**：编辑器后端可插拔（TinyMCE/CodeMirror 5/6/PlainEditor），命令服务架构统一快捷键/菜单/工具栏——这是它 52k★ 的根基。
- **调度保存 + OCR + 全平台**（含 Linux/CLI）。

#### 4. Relatum（仅 Windows，开源）—— 评级 B
**深层优点**
- **节点自由度最大化**：颜色/大小/圆角/透明度/字重/字号/对齐全可调——画布类工具里参数最全。
- **一键思维导图多布局** + Obsidian Canvas 格式兼容（开放、可迁移）。
- **学习闭环**：番茄钟/每日任务/间隔复习内置。

#### 5. Memos（MIT，自托管）—— 评级 A-
**深层优点**
- **极简到极致**：时间线优先、打开即写、写完即走——交互哲学比功能更有价值。
- **工程极简**：Go 单二进制 + SQLite + Docker 一键部署；REST + gRPC 双 API，可编程、无遥测。

#### 6. QOwnNotes（GPL）—— 评级 B+
**深层优点**
- **Nextcloud/ownCloud 深度整合**：纯文本 Markdown 文件 + 开源云同步闭环（数据全自主）。
- **脚本系统**：内置脚本 API 可深度定制；与移动端 Companion 配合拍照转文本。
- 单实例、系统深色联动等桌面细节扎实。

#### 7. Notes（nuttyartist，C++/Qt）—— 评级 B+
**深层优点**
- **纯键盘工作流**：全局热键 + 全快捷键 + 快捷键文档化——键盘流用户的最优解。
- **Markdown 转看板**（Kanban）是差异化功能；嵌套文件夹 + 全局标签双组织；三主题。

#### 8. nb（AGPL，命令行）—— 评级 A-（在命令行品类内）
**深层优点**
- **Git 即版本控制/备份/同步**：每次修改自动 commit——用 Git 解决了笔记的版本与同步两大难题，理念极聪明。
- Pandoc 多格式互通、加密、插件化子命令。

### 办公套件类

#### 9. ONLYOFFICE Personal（AGPL，WASM）—— 评级 A-
**深层优点**
- **WASM 纯前端**：docx/xlsx/pptx/PDF 编辑全部在浏览器本地完成，数据不出设备——隐私合规场景（如政府/医疗）的天然方案。
- **x2t 转换引擎成熟**：格式兼容性是商业级。

#### 10. Umo Editor（MIT，Vue3 + Tiptap3）—— 评级 A-
**深层优点**
- **ProseMirror/Tiptap3 架构**：编辑器内核可扩展性极强（命令、schema、插件体系）。
- **分页模式**：类 Word 的分页渲染 + 打印导出——Web 文档编辑器里的差异化。
- Markdown 语法 + 富文本双写、暗色主题、多语言。

#### 11. DzzOffice（PHP）—— 评级 C+
**深层优点**：多人在线协作 + 网盘集成 + 私有化部署。
**局限**：生态整合深于技术深度；PHP 老栈；面向内网协同而非文档质量。

#### 12. GenOffice（Apache 2.0，AI 原生）—— 评级 B+
**深层优点**
- **AI 原生设计**：块级编辑 + 快照 + diff——AI 改动可审阅、可撤销，是"AI 办公"的正确架构。
- **格式保真**：.docx 字节级保真 + Rust .xlsx 引擎；六合一编辑器共享引擎层。
- Apache 2.0 宽松许可，AI 集成路径干净。

#### 13. AbiWord（GPL-2，C++）—— 评级 C+（现代标准下）
**深层优点**：20+ 年稳定、轻量跨平台、低资源占用。
**局限**：无协作、无云、功能落后于现代 Office；适合低配环境/教育场景。

#### 14. Euro-Office（ONLYOFFICE 分支）—— 评级 B
**深层优点**：欧洲企业联合维护的"数据主权"叙事（欧盟合规）；双格式兼容（微软 + ODF）。
**局限**：依赖 ONLYOFFICE 上游演进，独立创新有限。

#### 15. Joeffice（Apache，纯 Java）—— 评级 C+
**深层优点**：NetBeans 模块化平台（文字/表格/演示/绘图/数据库独立模块）+ Apache POI 格式支持——模块化架构示范。
**局限**：单模块深度有限、Java 桌面体验一般。

### 总体结论
| 品类 | 第一梯队 | 关键启示 |
|------|----------|----------|
| 笔记 | Joplin（生态）、Trilium（组织模型）、Memos（极简工程） | 本地优先 + 开放格式 + 可编程是共同护城河 |
| 画布 | Relatum（节点自由度）、Lokus（性能） | 无限画布 + 参数自由 + 格式开放 |
| 办公 | ONLYOFFICE（本地化）、Umo（ProseMirror）、GenOffice（AI） | 格式保真 + 可扩展内核 + AI 可回退 |

**对本项目的启示**：我们已落地的（就地编辑/命令服务/脏矩形/全文搜索/小地图/单实例/导出）与
这些 A 级方案的共性高度一致；后续长线方向（版本历史 C2、标签 C3、PDF 导出 D2）对标 Joplin/Relatum 即可。

## 九、加密/密码盘专项研读（2026-08-13 补充）

> 为落地"U盘即钥匙"军工级密码盘，专项研读 5 个加密开源项目。
> 核心结论先行：**age 的密钥文件模式（key.txt 即钥匙）** 是"U盘即钥匙"最简
> 参考；**Cryptomator 的 vault 加密细节** 是文件加密的成熟范本。

### 1. age（23.2k★，Go）—— 密钥文件模式蓝本（最相关）
- **定位**：简单、现代、安全的文件加密工具（age-encryption.org/v1 开放格式）。
- **核心机制**：`age-keygen` 生成密钥文件 `key.txt`（含公钥+私钥）；加密用公钥
  `-r`，解密用私钥文件 `-i key.txt`。**密钥文件本身就是"钥匙"**——这正是
  "U盘即钥匙"的最简实现形态。
- **算法**：X25519 密钥交换 + ChaCha20-Poly1305（后量子支持）；scrypt 用于
  口令加密的私钥。
- **可借鉴点**：
  1. **密钥文件即钥匙**：U 盘存一个密钥文件，应用解密时从 U 盘读取——零知识、
     无密码也能解锁（插盘即开）；
  2. **文件头自包含**：每个加密文件头部携带解密所需全部信息（除密钥外），
     无共享元数据 = 无单点故障（与本项目"工程文件自包含"一致）；
  3. **格式版本化**：age 开放格式带版本，可升级兼容。

### 2. Cryptomator（15.9k★，Java）—— 文件加密成熟范本
- **定位**：云盘客户端加密（透明挂载，用户无感）。
- **核心机制**：AES-256 密钥；**scrypt 密钥派生**；随机盐/IV/主密钥；文件名
  加密 + 目录结构混淆；每个 vault 独立密码；认证加密（内容防篡改）；I/O
  原子事务写入；**敏感数据用后立即从堆内存擦除**。
- **可借鉴点**：
  1. **认证加密**（本项目已用 AES-256-GCM，天然防篡改）——方向完全一致；
  2. **内存擦除**：解密后的明文用完即 `null`，军工级细节（本项目可补）；
  3. **vault 结构**：密钥文件（masterkey）与数据分离——密码盘落地的结构参考；
  4. **多 vault 独立密码**：多个密码盘可并存，互不干扰。

### 3. VeraCrypt（11.2k★，C/C++）—— 军工级磁盘加密参考
- **定位**：全盘/容器加密（TrueCrypt 7.1a 的强化续作）。
- **核心机制**：XTS-AES 磁盘加密；**口令+随机盐+迭代 KDF**；隐藏卷（拒认）；
  Windows 驱动需**数字签名**（IDRIX 证书）才能加载。
- **可借鉴点**：驱动签名意识——Windows 发布组件需签名（政府项目发布时考虑
  代码签名）；隐藏卷思想可作远期"秘密盘"彩蛋。

### 4. KeePassXC（28.4k★，C++/Qt）—— 密码库 UX 参考
- **定位**：跨平台密码管理器。
- **核心机制**：Argon2id KDF + AES-256 加密数据库；数据库文件即"保险库"。
- **可借鉴点**：解锁交互（输密码→解锁→超时自动锁）与密码库文件独立性
  ——密码盘的"解锁/锁定"状态机可参照。

### 5. Picocrypt（1.6k★，Go，已归档）—— 极简加密工具参考
- **定位**：极简安全的单文件加密工具（XChaCha20 + Argon2id）。
- **状态**：2025-09 归档（作者停止维护），社区后继 Picocrypt NG。
- **可借鉴点**：XChaCha20 是 AES-GCM 之外的优秀备选（nonce 更长、抗滥用）；
  Argon2id 是比 scrypt 更新的 KDF——本项目若升级可考虑 Argon2id。

### 密码盘技术选型结论（供任务 2 设计使用）
| 维度 | 选择 | 依据 |
|------|------|------|
| 密钥形态 | **U 盘存密钥文件（零知识）** | age key.txt 模式 |
| 加密算法 | **AES-256-GCM**（已用）| Cryptomator/Aegis 同源 |
| KDF | **PBKDF2 10万次**（已用）→ 可选 Argon2id | KeePassXC/Picocrypt |
| 文件头 | Magic + 版本 + Salt + Nonce + 密文 | Aegis vault / age |
| 防篡改 | GCM 认证（已具备）| Cryptomator |
| 内存安全 | 解密后立即置 null | Cryptomator 铁律 |
| 恢复机制 | 24 位恢复密钥（纸备份）或密码盘重置 | Bitwarden/1Password 标准 |
| 发布 | Windows 组件代码签名（远期）| VeraCrypt 启示 |

### 对比式学习：压感笔刷 / 色域选色器 / 页面布局（2026-08-13）

用户要求"从头学习 Excalidraw 每一行代码，形成对比式学习：它的实现→好处→我的实现→差距→补齐"。

**① 压感笔刷**
- Excalidraw 实现：free-draw 记录 pointer.pressure（0~1）；鼠标无压感时用
  **速度模拟**——笔尖移动快→笔画细、慢→笔画粗；渲染按每点压力逐段变宽。
- 好处：真实书写感（轻重笔触），鼠标也能画出有灵魂的笔迹。
- 我的原实现：StrokePoint 已存 pressure 但鼠标恒 1.0、无速度模拟 → 笔迹均匀呆板。
- 差距：鼠标/触控板笔迹无轻重变化。
- 补齐：起笔记录位置/时间，_onPointerMove 计算速度→压力
  （pressure = clamp(1 - speed/3, 0.2, 1.0)）；触控/手写笔优先真实 pressure；
  渲染复用 StrokeRenderer 分段变宽。✅

**② 色域选色器**
- Excalidraw 实现：ColorPicker 模块 = Picker（S/V 二维色域方块 + Hue 条）+
  ShadeList 色阶 + TopPicks 常用色 + CustomColorList + ColorInput + 键盘导航。
