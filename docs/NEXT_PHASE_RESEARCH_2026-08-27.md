**日期：**2026-08-27

## 结论

当前项目不需要推倒重写。连续的对象编辑重构已将 `DocumentObjectEditingSession` 从 985 行降低至 737 行，并将变换、删除、命中和可见包围盒拆分为可直接测试的无状态协作者。下一阶段应优先完成同一会话中剩余的**混合对象快照构造与恢复边界**，而不是立即扩展新功能或再次拆分页面 Widget。

> 建议的下一项实施任务是新增 `DocumentObjectSnapshotService`，使快照捕获、深拷贝恢复、内容等价判定和当前图层索引修正成为独立、无 UI 的可测试协作者；会话继续拥有选择清理、缓存重建、通知与撤销命令编排。

## P0 的边界与验收标准

`DocumentObjectSnapshotService` 应只负责以领域对象为输入输出的快照构造、集合恢复、快照内容比较和索引修正。它不得持有 `DrawingController`、`DocumentObjectEditingHost`、选择状态、命令栈、缓存句柄或 Widget。

`DocumentObjectEditingSession` 应继续在恢复后修正当前选择、调用文档脏标记、重建缓存、发送状态通知及触发完整重建。该分工使撤销/重做的集合恢复可单测，并确保 UI 与运行时副作用仍由宿主边界协调。

验收时应至少新增以下直接测试：快照在原始对象随后修改时保持独立；恢复完整替换图层、形状和图片；当前图层索引被安全修正；恢复后不存在的选择 ID 被清理；缓存重建与通知恰好发生一次。仍须执行格式化、全量串行测试、静态分析、架构边界、差异检查以及远程 14 项门禁。
