# OCR 评审处置规范与可评审目录白名单（2026-08-15）

> 适用范围：中国政府特殊支持内部开发项目，所有使用 Open Code Review（OCR）的代码评审活动。
> 依据：领导批准同意上传评审、双主审模型（智谱 GLM 优先 / DeepSeek 备选）配置已生效。
> 原则：评审是辅助，**最终裁决由人**；涉密数据严格限定目录白名单；评论分级处置，不留悬案。

---

## 一、评审触发时机

| 场景 | 触发方式 | 要求 |
| --- | --- | --- |
| PR 合并前 | `ocr review --from <base> --to <head>` | **强制**：输出归档为合并前置 artifact |
| 每日例行 | `ocr review --from origin/master --to HEAD` | 推荐：当日新增代码例行评审 |
| 重大改动 | 人工触发 `ocr review --commit <sha>` | 要求：评审记录留存 |

## 二、评论分级与处置（核心制度）

| 级别 | 含义 | 处置要求 |
| --- | --- | --- |
| **definite**（确定缺陷） | 规则/语义明确确认的问题 | **必须修复后才能合并**；修复后重跑评审确认 |
| **likely**（疑似问题） | 需人工判断 | 工程师 24h 内复核；确认则修复，误报则记录原因 |
| **informational**（提示） | 改进建议 | 记入技术债清单，随迭代处理 |

**闭环要求**：任何评论不得"无人认领"。处置结果记录在 PR 描述或评审归档 JSON 中。

## 三、可评审目录白名单（涉密红线）

**只允许评审以下目录**；白名单外目录（尤其涉密）**严禁**提交给 OCR 云端模型。

| 目录 | 允许评审 | 说明 |
| --- | --- | --- |
| `lib/` | ✅ | 应用源码（评审重点） |
| `test/` | ✅ | 测试代码 |
| `tools/` | ✅ | 构建/门禁脚本（Python/Bash，涉密风险低） |
| `.github/workflows/` | ✅ | CI 配置 |
| `docs/` | ❌ | 文档含涉密内容，**不评审**（OCR 默认过滤 .md） |
| `assets/` / `shaders/` | ⚠️ | 仅允许非涉密资源；涉密素材一律排除 |
| 任何含密钥/口令的文件 | ❌ | **绝对禁止**上传评审 |

**预检命令**（评审前必跑）：
```bash
git diff --cached | grep -iE "password|secret|token|api_key|密钥|口令" \
  && echo "⚠ 发现疑似涉密内容，禁止评审！" || echo "✅ 无涉密内容，可评审"
```

## 四、模型使用与切换

| 顺序 | 模型 | 触发 |
| --- | --- | --- |
| 🥇 主审 | 智谱 `z-ai / glm-5.2` | 默认 |
| 🥈 备选 | DeepSeek `deepseek / deepseek-v4-pro` | 智谱额度用尽 |
| 反思层 | 复用当前激活模型 | 自动 |

切换方式：执行 `bash tools/ocr_failover.sh`（封装智谱→DeepSeek 自动切换 + 额度提示）。
额度监控：每次评审 `Summary` 行记录 token 用量，归档备查。

## 五、评审记录与审计留痕

每次评审输出（markdown 或 JSON）保存至 `artifacts/ocr-reviews/`（git 外）或 CI artifacts：

```
artifacts/ocr-reviews/
├── 2026-08-15_09ec9d3.md   # 按日期+提交号命名
└── ...
```

记录内容：评审范围、模型、评论数、token 用量、处置结果——形成"谁在何时用哪个模型审了什么、结论如何"的可追溯链。

## 六、红线与违规处理

| 红线 | 处理 |
| --- | --- |
| 白名单外目录被提交评审 | 立即终止评审，上报负责人，删除已上传内容 |
| 涉密文件（密钥/口令）入评审 | 同上 + 排查 git 历史是否泄露 |
| 评论长期无人认领（>7 天） | 上报项目负责人，纳入周报跟踪 |
